# Dragon Code 紧凑翼形 Banner Spec

## 背景

Dragon Code 当前使用红色三头龙 ASCII 图案作为启动 Banner，但该方案的视觉效果已被用户
明确否决。经过单独的视觉设计讨论，用户最终确认采用一个原创、无脸、抽象的 Unicode
翼形小图标，并将图标与产品信息并排展示。

本次改动只更新启动 Banner 的图案、颜色和信息排版，不改变 ch02 的对话功能。

## 目标

- 使用用户已经确认的 4×9 Unicode 翼形图标。
- 图标与产品名、版本、产品说明和工作目录并排展示。
- 图标与产品名使用白色，辅助信息使用灰色。
- 保持 Banner 紧凑，在常见终端宽度下清楚、稳定地显示。
- 不影响对话、Provider、输入、流式输出和其他界面区域。

## 功能需求

- F1：启动界面展示以下固定图标，字符和相对位置保持一致：

  ```text
   ▗▄   ▄▖
  ▐██▙▄▟██▌
  ▝██▀█▀██▘
    ▘   ▝
  ```

- F2：图标固定为 4 行，显示宽度为 9 列，保持无脸、抽象翼形构图。
- F3：图标右侧按行展示产品信息：
  - 第一行：`Dragon Code` 和当前版本号。
  - 第二行：`Multi-provider coding agent`。
  - 第三行：当前工作目录。
  - 第四行：不显示辅助文字。
- F4：图标和 `Dragon Code` 使用白色；版本号、产品说明和工作目录使用灰色。
- F5：Banner 继续显示运行时的真实版本号和当前工作目录。
- F6：原有独立的就绪提示、对话区、输入框、计时和状态栏保持不变。
- F7：旧的红色三头龙图案不再显示。

## 非功能需求

- N1：图标必须使用交接文档中已经批准的 Unicode 字符，不擅自增删或替换字符。
- N2：图标与右侧文字之间保持清楚、稳定的间距，各行信息正确对齐。
- N3：标准终端和约 42 列的窄终端中，Banner 不得与其他界面区域重叠。
- N4：样式实现保持简单，代码包含必要的中文说明，不引入新的第三方依赖。
- N5：工作目录中的特殊字符不能被当作样式标记解析，也不能破坏界面。
- N6：现有自动测试、格式检查和静态检查继续通过。
- N7：API Key 不出现在 Banner、测试输出或日志中。

## 不做的事

- 不再讨论或重新设计图标的题材、颜色、尺寸和字符。
- 不恢复三头龙、完整像素龙、大型字符画、表情脸或红色描边。
- 不制作 PNG、SVG、应用图标或 README Logo。
- 不加入动画、闪烁、渐变、随机效果或交互效果。
- 不修改就绪提示的文字。
- 不改变对话、Provider、流式输出、输入框、状态栏或配置格式。
- 不引入新的依赖。

## 验收标准

- AC1：启动 Dragon Code 后，顶部显示与交接文档完全一致的 4×9 Unicode 翼形图标。
- AC2：第一行右侧显示 `Dragon Code` 和真实版本号，第二行显示
  `Multi-provider coding agent`，第三行显示真实工作目录。
- AC3：图标和 `Dragon Code` 为白色，版本、产品说明和工作目录为灰色。
- AC4：旧红色三头龙图案及其箭头、眼睛和环形轮廓不再出现。
- AC5：标准终端和约 42 列的窄终端中，图标与文字保持可读，不与对话区或输入区重叠。
- AC6：带空格、方括号等特殊字符的工作目录能够原样显示，不触发样式解析错误。
- AC7：就绪提示、Provider 状态、输入和对话功能与修改前一致。
- AC8：Banner 专项测试、完整 pytest、Ruff 格式检查和静态检查全部通过。
