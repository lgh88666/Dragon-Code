# Dragon Code 权限系统 Spec

## 背景

Dragon Code 已具备六个核心工具、流式工具调用、ReAct Agent Loop、Plan Mode 和结构化系统提示。模型能够自主读取、搜索、修改文件和执行命令，并根据工具结果持续行动。

目前工具执行链路没有强制安全闸门。写文件工具可以写入任意位置，命令工具可以运行高危操作，读取工具也可能接触项目外的敏感文件。System Prompt 只能引导模型，不能可靠阻止提示注入、越权操作和数据泄露。

ch06 将在工具调用真正执行前增加五层防御，使 Dragon Code 从“能够自主工作”升级为“在安全边界内自主工作”。

## 目标

- **五层串联**：每次工具调用依次经过危险命令黑名单、路径沙箱、规则引擎、权限模式兜底和 HITL。
- **逐层短路**：任一层得到明确的 Allow 或 Deny 后立即结束判断；未作决定时才进入下一层。
- **统一判断结果**：权限判断使用 Allow、Deny、Ask 三种结果；权限模式只产生 Allow 或 Ask。
- **危险命令硬拦截**：内置黑名单不可配置关闭，任何规则和模式都不能放开命中的高危命令。
- **跨平台防护**：黑名单覆盖 Unix/Linux、PowerShell、CMD 和 WSL 的典型高危操作。
- **路径沙箱**：文件和搜索工具只能访问启动时的单一项目根目录，并防止相对路径与符号链接逃逸。
- **细粒度规则**：支持按照“工具名 + 参数或路径模式”配置精确规则和 glob 规则。
- **三级规则优先级**：规则按本地级、项目级、用户级逐层判断；在同一层内 deny 优先于 allow。
- **四档权限模式**：提供 default、acceptEdits、plan、bypassPermissions 四档信任等级。
- **运行时模式切换**：空闲状态下通过 Shift+Tab 循环切换模式，当前模式在状态栏持续可见。
- **人在回路**：模式判为 Ask 时暂停 Agent Loop，让用户选择允许本次、永久允许或拒绝本次。
- **精确永久授权**：永久允许只保存当前工具调用的精确规则，不自动扩大授权范围。
- **拒绝后继续调整**：权限拒绝以结构化工具结果回灌，不终止 Agent Loop，让模型调整路径或策略。
- **Plan Mode 不退化**：`/plan` 继续只提供只读工具，`/do` 继续按计划执行。
- **跨协议一致**：权限判断位于 Agent 编排层，不修改 Anthropic 和 OpenAI 的 LLM Client。
- **既有能力不退化**：保留工具并发、任务取消、历史合法性、缓存和 system-reminder 等能力。

## 功能需求

- **F1 危险命令黑名单**：命令执行类工具在执行前必须与内置高危模式匹配；命中后立即 Deny，不执行命令。黑名单不可增加、删除、关闭或被任何规则和模式绕过，包括 bypassPermissions。覆盖 Unix/Linux、PowerShell、CMD 和 WSL 的典型系统破坏操作。黑名单属于启发式防御，不承诺覆盖所有危险命令。

- **F2 路径沙箱**：Read、Write、Edit、Glob、Grep 的目标路径或搜索根必须位于启动时的单一项目根目录。判断时先规整绝对路径并解析符号链接，再检查真实路径是否仍在项目内。对于尚不存在的新文件或中间目录，检查最近的已存在祖先目录。Bash 不做路径沙箱，因为无法可靠静态分析任意命令访问的文件。

- **F3 权限规则匹配**：规则使用 `工具名(模式)` 表示，例如 `Bash(git status)`、`Bash(git *)`、`Write(src/**)`；省略模式表示匹配该工具的全部调用。每条规则结果只有 allow 或 deny。命令规则匹配完整命令串；文件规则匹配项目相对路径。命令中的 `*` 和 `**` 都匹配任意字符序列；文件路径中的 `*` 匹配单段，`**` 可跨目录匹配。

- **F4 三级配置加载**：从用户级、项目级、本地级三份 YAML 设置中加载权限规则和可选的默认模式。判断优先级为本地级 → 项目级 → 用户级，在最高优先级的命中层作出决定；同一层内 deny 优先于 allow。配置缺失视为空规则；单个配置格式错误时安全降级为空，不影响其他层加载，也不导致程序崩溃。启动默认模式同样按本地 → 项目 → 用户取值，均未配置时使用 default。

- **F5 权限模式兜底**：规则未命中时，根据工具类别和当前模式产生 Allow 或 Ask，模式层不直接产生 Deny。

  | 模式 | 只读工具 | 文件写工具 | 命令执行 |
  |---|---|---|---|
  | default | Allow | Ask | Ask |
  | acceptEdits | Allow | Allow | Ask |
  | plan | Allow | Ask | Ask |
  | bypassPermissions | Allow | Allow | Allow |

  bypassPermissions 仍需经过黑名单、路径沙箱和显式权限规则。plan 继续只向模型提供只读工具；矩阵中的 Write 与 Bash Ask 作为防御性兜底。

- **F6 五层判定流水线**：每个工具调用在真正执行前依次经过黑名单、路径沙箱、规则引擎和模式兜底；模式返回 Ask 时进入第五层 HITL。黑名单只检查命令执行类工具，沙箱只检查文件和搜索工具；不适用的层直接跳过并继续。任一层产生明确 Allow 或 Deny 后立即短路。

- **F7 运行时模式切换**：空闲状态下按 Shift+Tab，按照 default → acceptEdits → plan → bypassPermissions → default 循环切换。当前模式跨对话轮次保持，并在状态栏左侧常驻显示，取代 provider 名称。`/plan` 仍可进入计划模式；`/do` 退出计划模式、切回 default，并立即按已确认计划执行。

- **F8 人在回路审批**：模式判为 Ask 时暂停 Agent Loop，在对话区显示工具名、关键参数、触发原因和三项菜单。默认高亮“允许本次”；用户可以使用上下方向键与 Enter，也可以使用数字键选择：
  1. 允许本次：执行当前调用，不保存规则。
  2. 永久允许：执行当前调用，并把精确 allow 规则写入本地级设置。
  3. 拒绝本次：不执行工具，生成结构化拒绝结果。

  一次回复包含多个待确认调用时，按模型给出的顺序逐个审批。等待审批时按 Esc 或 Ctrl+C 取消整个当前 Agent 任务，不退出程序。

- **F9 拒绝结果回灌**：黑名单、沙箱、deny 规则或用户拒绝产生的 Deny，都转换为包含拒绝来源和可读原因的结构化工具结果，按照原工具调用 ID 和顺序写入历史。拒绝不终止 Agent Loop，模型可以根据结果修改命令、路径或策略。同一批中被拒绝和被允许的调用互不影响，结果仍按原顺序配对。

- **F10 安全默认**：未知工具、参数无法解析、缺少必要路径、工具类别无法判断等不确定情况不得静默放行。文件目标无法可靠解析时直接 Deny；未知或类别不明的工具按有副作用操作处理并进入 Ask 或 Deny。

- **F11 跨协议一致**：权限系统位于 Agent 编排与工具执行之间，不进入 LLM Client。Anthropic、OpenAI 和兼容端点使用完全相同的权限判定、审批、拒绝回灌和取消行为。

## 非功能需求

- **N1 黑名单不可绕过**：危险命令黑名单始终是最高优先级防线，不存在任何配置、规则、模式或 HITL 选择可以放行命中的命令。
- **N2 沙箱防逃逸**：路径判断必须先解析符号链接，再进行项目根边界检查；不能只比较用户输入的字面路径。新建目标需要通过最近的已存在祖先进行安全判断。
- **N3 界面保持响应**：权限判断和 HITL 等待期间，TUI 仍能刷新、滚动和接收审批或取消按键，不因 Agent Loop 等待用户决定而冻结。
- **N4 审批可取消且不死锁**：等待审批时取消当前任务，必须释放所有等待状态和未完成任务，回到空闲状态；不得残留挂起的异步任务、未关闭的队列或永远等待的审批请求。
- **N5 历史保持合法**：权限拒绝、审批取消以及同批工具部分允许、部分拒绝后，工具调用和结果仍按调用 ID 正确配对，消息角色顺序合法，后续请求不会因历史结构错误返回 400。
- **N6 既有能力不退化**：ch04/ch05 的多轮 Agent Loop、流式双路收集、保序分批并发、用户取消、缓存、system-reminder 和 Plan Mode 行为继续成立。连续只读调用不能因为新增权限检查退化为串行。
- **N7 配置安全降级**：权限配置不存在、无法读取、YAML 非法、规则格式错误或默认模式未知时，使用不额外放开权限的安全默认值；程序不崩溃，也不输出未捕获堆栈。
- **N8 不确定情况从严处理**：未知工具、参数解析失败、路径提取失败和类别不明等情况必须 Ask 或 Deny，不能因为系统无法判断而自动 Allow。
- **N9 跨协议一致**：权限行为与模型协议无关；Anthropic、OpenAI 和兼容端点均使用相同的判定顺序、UI 交互和拒绝结果。
- **N10 敏感信息不泄漏**：权限配置、审批界面、拒绝结果和错误信息不得显示 API Key、环境变量秘密或无关的本地敏感内容。
- **N11 跨平台一致**：路径边界和危险命令判断在 Windows、Unix/Linux 与 WSL 环境下使用对应的平台语义，不因路径分隔符、盘符大小写或命令格式差异产生明显绕过。
- **N12 结果顺序稳定**：一次回复中的多个工具调用无论允许、拒绝还是审批等待，最终结果都按模型原始调用顺序回灌，不因并发完成顺序而错位。
- **N13 代码质量**：新增代码保持简单、使用中文注释解释关键安全判断；项目格式化、lint 和自动化测试全部通过。
- **N14 可扩展性**：以后新增权限模式、规则来源或防御层时，改动应局限在权限系统和编排接入点，不需要修改 Anthropic/OpenAI 的 LLM Client。

## 不做的事

- **不限制网络访问**：本章不分析或限制 Bash、模型接口及其他组件的出网行为。
- **不做资源配额**：不增加 CPU、内存、磁盘、Token、执行次数或速率配额。
- **不做审计日志**：不持久化记录每次权限判断、审批人、审批时间和执行结果。
- **不开放黑名单配置**：用户不能增加、删除、覆盖或关闭内置危险命令规则。
- **不自动泛化永久规则**：永久允许只保存当前工具调用的精确规则；`Bash(git *)`、`Write(src/**)` 等通配规则需要用户手动编写。
- **不支持本会话授权**：HITL 不提供“本会话内始终允许”；只有允许本次、永久允许和拒绝本次。
- **不覆盖外部工具**：本章权限系统只覆盖 Read、Write、Edit、Bash、Glob、Grep 六个内置工具，不处理未来的 MCP 工具和自定义工具。
- **不为 Bash 建立路径沙箱**：不尝试静态推断 Bash 命令可能读取或修改的所有路径；Bash 由黑名单、权限规则、模式和 HITL 约束。
- **不支持多个项目根**：路径沙箱只使用启动时的单一项目根，不自动允许系统临时目录，也不支持配置额外白名单目录。
- **不做操作系统级隔离**：不使用容器、虚拟机、受限用户或 OS Sandbox 隔离命令执行。
- **不做图形化规则管理**：不提供规则列表、规则编辑器或删除规则界面；规则通过 YAML 文件管理，永久允许只负责追加本地精确规则。
- **不增加更多权限模式**：本章模式固定为 default、acceptEdits、plan、bypassPermissions，不增加 strict 或自定义模式。
- **不扩展 Slash Command 体系**：不新增 `/permissions` 等命令；运行时模式切换使用 Shift+Tab，计划工作流继续使用 `/plan` 和 `/do`。
- **不重写搜索遍历逻辑**：Glob 和 Grep 只校验搜索根目录，内部遍历继续沿用现有“不主动跟随目录符号链接”的行为。

## 验收标准

- **AC1 黑名单硬拦截**：在 default 和 bypassPermissions 模式下请求执行典型高危命令，均被拒绝且命令没有实际运行；拒绝结果说明命中了危险命令黑名单。（F1）
- **AC2 跨平台危险命令**：Unix/Linux、PowerShell 和 CMD 各至少一种等价高危操作能够被识别；普通删除构建目录、查看状态等正常命令不被误判。（F1）
- **AC3 路径沙箱边界**：项目内已有文件和多级目录尚未创建的新文件可以通过路径检查；项目外绝对路径、`../` 越界路径和项目内指向项目外的符号链接均被拒绝。（F2）
- **AC4 规则精确与通配匹配**：精确规则只匹配指定调用；命令 glob 能匹配同类命令；文件 `*` 与 `**` 分别表现为单段和跨目录匹配；独立 deny 规则命中后拒绝。（F3）
- **AC5 友好工具名路由**：Bash、Read、Write、Edit、Glob、Grep 六种规则名称分别作用于对应内置工具，不串用、不漏用。（F3）
- **AC6 三级规则优先级**：本地级规则优先于项目级，项目级优先于用户级；同层 allow 与 deny 同时命中时选择 deny。（F4）
- **AC7 配置安全降级**：三层设置全部缺失时以 default 和空规则启动；任一层 YAML 非法或含非法规则时只跳过问题内容，其余层继续生效，程序不崩溃。（F4）
- **AC8 启动默认模式**：本地、项目、用户分别配置不同默认模式时，按本地 → 项目 → 用户选择；均未配置或模式名非法时使用 default。（F4）
- **AC9 模式矩阵**：逐一验证四种模式下只读、文件写和命令执行三类工具，得到与功能需求矩阵一致的 Allow 或 Ask；bypassPermissions 仍遵守黑名单、沙箱和显式规则。（F5）
- **AC10 流水线短路与跳层**：黑名单命中后不再进入规则和模式；沙箱拒绝后不再进入 HITL；allow 规则命中后直接执行；不适用的层被跳过但后续权限判断继续。（F6）
- **AC11 模式切换与显示**：空闲状态连续按 Shift+Tab，模式按照 default → acceptEdits → plan → bypassPermissions → default 循环；状态栏左侧显示当前模式且不再显示 provider 名，模式跨对话轮次保持。（F7）
- **AC12 Plan Mode 保持不变**：通过 Shift+Tab 或 `/plan` 进入 plan 后，模型只获得 Read、Glob、Grep；`/do` 切回 default 并立即按已有计划执行。（F5/F7）
- **AC13 HITL 三选一**：default 下请求 Write、Edit 或 Bash 时出现包含工具、关键参数、原因和菜单的确认块；方向键与 Enter、数字键 1/2/3 都可完成选择，默认高亮允许本次。（F8）
- **AC14 永久精确授权**：选择永久允许后当前调用被执行，本地设置中新增且只新增对应的精确 allow 规则；重启 Dragon Code 后相同调用不再询问，不同参数的调用仍需判断。（F8）
- **AC15 拒绝回灌并继续**：选择拒绝或命中黑名单、沙箱、deny 规则后，模型收到结构化拒绝结果；Agent Loop 继续，模型能够改用安全路径或其他策略完成任务。（F9）
- **AC16 多调用保序配对**：同一批包含允许、拒绝和需要确认的多个调用时，逐个审批顺序与模型调用顺序一致；最终结果按原顺序和调用 ID 回灌，互不串位。（F8/F9）
- **AC17 审批期间取消**：HITL 等待时按 Esc 或 Ctrl+C，整个当前 Agent 任务被取消，程序回到空闲状态且不退出；之后可以继续发送消息，不出现历史结构错误或挂起任务。（F8）
- **AC18 安全默认**：未知工具、非法 JSON、缺少路径和类别不明的调用均不会被直接执行，而是 Ask 或 Deny。（F10）
- **AC19 只读并发不退化**：连续多个只读调用仍能并发执行，不出现 HITL；其中一个只读调用被沙箱拒绝时，其他合法调用仍能完成，最终结果保持原顺序。（F6/F9）
- **AC20 跨协议一致**：分别通过 Anthropic 与 OpenAI/兼容端点运行相同权限场景，得到一致的允许、询问、拒绝、取消和回灌行为；LLM Client 不包含权限判断逻辑。（F11）
- **AC21 既有能力回归**：多轮 Agent Loop、流式文本、工具并发、Plan Mode、system-reminder、缓存字段、任务取消和合法历史相关测试继续通过。
- **AC22 代码质量与安全**：全部自动化测试、格式化和 lint 检查通过；新增关键安全逻辑有易懂的中文注释；运行输出、审批界面和错误信息不泄漏 API Key。
