# Dragon Code 权限系统 Checklist

> 每一项都通过运行测试、启动程序或观察行为验证。涉及真实高危命令的项目只使用测试替身验证，绝不在本机实际执行破坏性命令。

## 功能行为

- [ ] **危险命令硬拦截**：default 与 bypassPermissions 下的高危 Bash 调用均返回黑名单拒绝，命令执行替身未被调用。（验证：运行黑名单与权限引擎测试，检查执行计数为 0。）`AC1/F1`
- [ ] **跨平台黑名单**：Unix/Linux、PowerShell、CMD、WSL 各至少一个高危样例命中；普通项目目录清理、Git 和查看状态命令不误报。（验证：运行参数化黑名单测试。）`AC2/F1/N11`
- [ ] **沙箱边界**：项目内文件和多级新建路径通过；项目外绝对路径、`../`、项目内指向项目外的符号链接被拒绝。（验证：在临时目录运行沙箱测试，符号链接不受平台支持时明确跳过。）`AC3/F2/N2`
- [ ] **规则精确与 glob**：精确规则不扩大匹配；命令 `*`/`**`、文件 `*`/`**` 和转义通配符按设计生效。（验证：运行规则匹配参数化测试。）`AC4/F3`
- [ ] **六工具规则路由**：Bash、Read、Write、Edit、Glob、Grep 规则只匹配对应工具及其规定参数。（验证：对六工具分别构造命中/不命中调用。）`AC5/F3`
- [ ] **三级规则优先级**：本地层覆盖项目层，项目层覆盖用户层；同层 deny 胜过 allow。（验证：创建三份冲突配置并运行规则仓库测试。）`AC6/F4`
- [ ] **配置安全降级**：三层均缺失、单层 YAML 非法、单条规则非法时仍能启动；问题内容不生效，其余合法层继续生效。（验证：分别构造配置后加载，无未捕获堆栈。）`AC7/F4/N7`
- [ ] **默认模式优先级**：本地、项目、用户的合法 mode 按顺序选择；全部缺失或非法时使用 default。（验证：运行默认模式参数化测试。）`AC8/F4`
- [ ] **四模式矩阵**：default、acceptEdits、plan、bypassPermissions 对只读、文件写、Bash 分别得到设计中的 Allow/Ask；bypass 仍受硬防线和显式规则限制。（验证：运行 4×3 参数化测试和前置拒绝测试。）`AC9/F5`
- [ ] **五层短路**：黑名单拒绝后不检查规则/模式，沙箱拒绝后不弹审批，allow 规则命中后不进入模式；不适用层会继续。（验证：使用记录调用次数的测试替身。）`AC10/F6`
- [ ] **模式循环与状态栏**：空闲时连续按 Shift+Tab 按 default → acceptEdits → plan → bypassPermissions → default 循环；左侧显示模式，右侧模型和 Token 保持。（验证：Textual pilot + tmux 手动观察。）`AC11/F7`
- [ ] **Plan Mode 双保险**：Shift+Tab 或 `/plan` 进入后只向模型提供 Read、Glob、Grep；`/do` 切回 default 并执行已有计划。（验证：检查 Fake Client 请求工具定义并跑 TUI 命令测试。）`AC12/F5/F7`
- [ ] **HITL 三选一**：default 下 Write/Edit/Bash 出现工具摘要、原因和三项菜单；方向键/Enter及数字 1/2/3 可操作，默认高亮允许本次。（验证：Textual pilot 与 tmux 各执行一次。）`AC13/F8`
- [ ] **永久精确授权**：选择永久允许后本地设置新增唯一精确规则；重启后相同路径/命令不再询问，不同调用仍需审批。（验证：使用临时项目保存、重载并匹配，再做 tmux 对话。）`AC14/F8`
- [ ] **拒绝回灌并继续**：黑名单、沙箱、deny 规则和用户拒绝均形成含来源原因的 ToolResult；Agent Loop 不崩溃，模型可调整策略。（验证：Fake Client 连续返回“被拒绝后改用安全调用”的响应。）`AC15/F9`
- [ ] **多调用保序配对**：同批允许、拒绝、询问混合时，审批按模型顺序出现，最终 ToolResult 按原 call_id 和顺序回灌。（验证：构造三调用集成测试。）`AC16/F8/F9/N12`
- [ ] **审批中取消**：确认框打开时 Esc/Ctrl+C 取消当前 Agent 任务而非退出应用；确认框关闭、输入恢复，之后还能正常对话。（验证：Textual pilot + tmux 手动操作，检查无 pending task 警告。）`AC17/F8/N4`
- [ ] **不确定情况从严**：未知工具、非法 JSON、缺少路径、错误类型、类别不明均不会被直接执行。（验证：逐类构造 ToolCall，期望 Ask/Deny/unknown_tool 结果。）`AC18/F10/N8`
- [ ] **只读并发不退化**：多个合法只读工具仍重叠执行；其中一个被沙箱拒绝时其他合法调用完成，结果仍保序。（验证：带 asyncio Event 的 Agent 集成测试。）`AC19/F6/F9/N6`
- [ ] **跨协议一致**：Anthropic 与 OpenAI/兼容端点的相同 ToolCall 经过同一权限系统，允许、询问、拒绝和回灌格式一致；Client 中无权限分支。（验证：两类 Fake Client 集成测试和请求体测试。）`AC20/F11/N9`
- [ ] **ch04/ch05 行为不退化**：Agent Loop、流式双路收集、工具并发、Plan Mode、system-reminder、缓存用量和取消测试继续通过。（验证：运行相关原测试集合。）`AC21/N6`
- [ ] **代码质量与脱敏**：全部测试、格式化和 lint 通过；关键安全判断有中文注释；输出中不含 API Key 或真实敏感配置。（验证：运行全套检查并搜索测试输出。）`AC22/N10/N13`

## 集成与历史

- [ ] **拒绝结果结构完整**：拒绝结果包含原 call_id、tool_name、`success=false`、错误码、可读原因和拒绝来源 metadata。（验证：检查 Agent 集成测试中的 ToolResult。）
- [ ] **Anthropic 历史合法**：拒绝/取消后的 assistant tool_use 与 user tool_result 完整配对，再发一轮请求不会产生协议格式错误。（验证：检查 Anthropic 请求体测试。）`N5`
- [ ] **OpenAI 历史合法**：拒绝/取消后的 assistant tool_calls 与 tool 消息按 ID 配对，再发一轮请求不会产生协议格式错误。（验证：检查 OpenAI 请求体测试。）`N5`
- [ ] **永久规则立即生效**：保存本地规则后同一进程中的下一次相同调用直接命中，不依赖重启。（验证：保存后立即调用 RuleStore.match。）
- [ ] **永久保存失败可恢复**：模拟只读目录/写入失败，当前调用仅允许本次，界面显示非致命警告，Agent Loop 继续。（验证：mock 写入异常并消费 warning 事件。）
- [ ] **审批等待不阻塞界面**：确认框显示时计时仍刷新、对话区可滚动、按键可响应。（验证：Textual pilot 推进时钟 + tmux 观察。）`N3`
- [ ] **取消无异步泄漏**：审批取消后 Approval Future、工具 task 和 Agent worker 均结束。（验证：pytest 无“Task was destroyed but it is pending”警告。）`N4`
- [ ] **权限模块边界清晰**：新增模式、规则来源或防御层无需修改 Anthropic/OpenAI Client。（验证：权限测试使用协议无关模型，Client 回归保持原接口。）`N14`

## 构建与自动化测试

- [ ] **权限模块可导入**：`uv run python -c "import dragon_code.permissions"` 成功。
- [ ] **应用可启动**：合法模型配置下 `uv run dragon-code` 能进入 TUI，权限设置缺失时默认使用 default。
- [ ] **格式正确**：`uv run ruff format --check .` 通过。
- [ ] **Lint 正确**：`uv run ruff check .` 无告警。
- [ ] **全部测试通过**：`uv run pytest -q` 全部通过；仅操作系统确实不支持的符号链接测试允许明确 skip。
- [ ] **本地规则不入库**：`.dragon-code/settings.local.yaml` 被 `.gitignore` 忽略，示例和项目级设置仍可跟踪。
- [ ] **敏感信息不回显**：运行输出、pytest 捕获输出和拒绝原因中均找不到配置中的 API Key。（验证：使用专用假 key 运行并搜索输出。）

## tmux 端到端场景

> 在 WSL tmux 中从项目目录启动 Dragon Code，使用真实可用模型进行以下操作。危险命令硬拦截只在自动化测试中使用进程替身验证，不向真实 shell 提交破坏性命令。

- [ ] **场景 1——允许本次**：default 启动 → 请求“读取 README.md，并把一句摘要写入 `permission-e2e/allow-once.txt`” → Read 自动执行 → Write 弹出审批 → 选择“允许本次” → 文件真实生成 → 模型继续并完成答复。
- [ ] **场景 2——拒绝后调整**：请求写入 `permission-e2e/deny-once.txt`，并说明“若被拒绝就停止写入并解释原因” → 选择拒绝本次 → 文件不存在 → 模型收到拒绝结果并给出说明 → 会话仍可继续。
- [ ] **场景 3——永久精确允许**：请求写入固定路径 → 选择永久允许 → 检查 `settings.local.yaml` → 重启后重复同一路径不再询问 → 换另一路径仍出现询问。
- [ ] **场景 4——模式切换**：连续按 Shift+Tab 观察四模式与状态栏 → 在 acceptEdits 写项目文件无需询问、Bash 仍询问 → 切到 bypassPermissions 后普通 Bash 无需询问。
- [ ] **场景 5——Plan Mode**：`/plan` 规划一个需要读写的任务 → 规划阶段只出现 Read/Glob/Grep → `/do` 切回 default → 首个写操作按 default 弹出审批。
- [ ] **场景 6——沙箱拒绝**：请求读取预先创建在项目外的无敏感测试文件 → 工具行显示沙箱拒绝 → 外部文件内容没有回灌 → 模型说明无法越过项目根。
- [ ] **场景 7——审批中取消**：触发 Bash 或 Write 确认框 → 按 Esc → 当前任务取消、应用不退出 → 再发送“只回复 OK”并正常收到回复。
- [ ] **场景 8——scrollback 与窄屏**：完成多个权限场景后回滚查看工具行、审批结果和最终回复顺序 → 缩窄 tmux 窗口，确认框、对话区和状态栏不重叠。
- [ ] **场景 9——跨协议**：用 Anthropic 配置完成一个允许/拒绝流程；用 OpenAI 或兼容 Fake/本地端点完成同一流程，观察上层行为一致。
