# Dragon Code 工具系统 Spec

## 背景

ch02 已打通“用户 ↔ LLM”的终端对话闭环，支持 Anthropic 与
OpenAI/DeepSeek 兼容协议、流式输出、多轮上下文和 TUI 展示。

目前模型只能生成文字，无法读取项目文件、修改代码或执行命令。ch03
将为 Dragon Code 增加工具系统：模型根据用户请求选择工具，Dragon Code
执行工具并把结果返回给模型，使其能够基于真实项目内容完成任务。

本章采用统一的内部事件模型屏蔽协议差异。Anthropic 与 OpenAI
协议分别负责转换请求和流式响应，上层工具系统保持一致。

## 目标

- 建立统一的工具抽象和集中注册机制。
- 提供读文件、写文件、改文件、执行命令、按模式找文件、搜索代码内容六个核心工具。
- 让模型在 Anthropic 和 OpenAI/DeepSeek 协议下都能发现并调用工具。
- 正确解析流式传输的工具调用，包括被拆分传输的工具名称和 JSON 参数。
- 为工具执行提供超时、参数校验、输出限制和结构化错误处理。
- 将工具调用及结果正确回灌对话历史。
- 完成一次“模型请求工具 → 执行工具 → 回灌结果 → 模型最终答复”的单轮闭环。
- 在 TUI 中实时展示工具调用、执行状态和结果摘要。
- 为工具保留安全分类及并发能力元信息，供后续权限系统和 Agent Loop 使用。
- 保持代码结构简单、命名直观，并为关键逻辑添加中文注释。

## 功能需求

- **F1：统一工具抽象**
  每个工具都提供名称、用途描述、参数 Schema、执行入口，以及
  `category`、`read_only`、`destructive`、`is_concurrency_safe`
  元信息。模型可根据名称、描述和参数 Schema 判断何时以及如何使用工具。

- **F2：工具注册中心**
  集中登记全部工具，支持列出工具、按名称查找工具，并能针对当前协议导出模型
  API 所需的工具定义。工具名重复或请求未知工具时返回清晰错误。

- **F3：六个核心工具**
  - **读文件**：读取工作目录内的文本文件，返回带行号的内容；文件不存在、
    无法读取或内容过大时给出明确结果。
  - **写文件**：在工作目录内创建或覆盖文件；父目录不存在时自动创建。
  - **改文件**：使用“原文片段 → 新文片段”进行精确替换；原文恰好匹配一次才
    执行，匹配零次或多次时不修改文件，并报告实际匹配数。
  - **执行命令**：从启动工作目录执行命令，返回标准输出、标准错误和退出码；
    支持超时终止。命令不受文件工具的路径限制，本章不提供命令沙箱。
  - **按模式找文件**：在工作目录内根据 glob 模式查找文件，返回匹配路径。
  - **搜索代码内容**：在工作目录内按搜索模式查找内容，可指定搜索范围，返回
    文件、行号和命中内容。

- **F4：文件访问范围**
  除执行命令外，所有文件与搜索工具只能访问 Dragon Code 启动工作目录及其
  子目录。绝对路径和相对路径都必须经过范围检查；越界访问不执行，并返回
  结构化错误。

- **F5：工具定义注入请求**
  每次正常对话请求都向模型提供当前六个工具的名称、描述和参数 Schema。内置
  系统提示词说明 Dragon Code 的 Agent 身份、工具能力和使用约定。

- **F6：流式工具调用解析**
  正确区分正文文本、思考内容和工具调用。工具名称及 JSON 参数可能分片到达，
  系统必须按照调用标识正确拼接。一次模型回复可以包含一个或多个工具调用；
  思考内容接收但不展示。Anthropic 工具续答所需的 `thinking` 与
  `redacted_thinking` 内容块仅在协议历史中原样保留和回灌，绝不渲染到 TUI。

- **F7：工具执行与结构化结果**
  按名称找到工具，校验参数后执行。一次回复中的多个工具按出现顺序全部执行。
  成功和失败都生成统一的结构化结果；单个工具失败不会造成程序崩溃，也不会
  阻止同批次其他工具执行。

- **F8：结果回灌与单轮续答**
  将模型发出的全部工具调用及对应结果追加到对话历史，再请求模型生成一次最终
  文字答复。若续答阶段再次请求工具，系统不再执行，并以可理解的单轮上限提示
  结束当前用户请求。

- **F9：跨协议一致性**
  Anthropic 与 OpenAI/DeepSeek 兼容协议都支持工具定义注入、流式调用解析、
  结果回灌和最终续答。上层对话与工具执行流程不依赖具体协议。

- **F10：TUI 工具展示**
  工具调用到达后，实时显示 Claude Code 风格工具行，例如
  `● Read(src/app.py)`。执行完成后显示成功或失败摘要；过长内容只展示摘要。
  这些记录进入对话区的滚动历史。

- **F11：会话恢复能力**
  JSON 参数无效、参数缺失、未知工具、文件错误、搜索无结果、命令非零退出或
  执行超时，都以可区分的结果呈现并回灌给模型。完成本轮后，用户仍能继续下一轮
  对话。

## 非功能需求

- **N1：执行超时**
  命令执行和可能长时间运行的工具使用内置超时。超时后应停止当前工具并返回
  结构化超时结果，不让会话永久等待。

- **N2：界面保持响应**
  网络流式接收和工具执行期间，TUI 不冻结；计时、状态提示和滚动操作仍能正常
  更新。

- **N3：结果体量控制**
  读取大文件、命令长输出、海量 glob 匹配及大量搜索命中时设置固定上限。超出
  部分截断，并在结果中明确说明已截断，避免撑爆模型上下文和终端界面。

- **N4：健壮性**
  参数类型错误、JSON 拼接失败、非法路径、编码问题、工具异常及协议响应异常都
  不得产生未捕获异常或直接展示程序堆栈。错误应转换为用户和模型都能理解的结果。

- **N5：跨协议体验一致**
  使用 Anthropic 或 OpenAI/DeepSeek 兼容协议时，工具触发、执行顺序、TUI
  展示、错误反馈及单轮结束规则保持一致。

- **N6：密钥安全**
  API 密钥不得出现在工具描述、命令展示、工具结果、对话区或错误信息中；现有
  ch02 的错误脱敏行为继续保留。

- **N7：跨平台兼容**
  六个工具和工具闭环需要在项目当前使用的 Windows 环境正常工作，并可在 WSL
  环境中通过 tmux 进行端到端验收。

- **N8：代码可读性**
  优先使用直观的数据类、普通函数和清晰的分支逻辑，避免不必要的高级语法与过度
  抽象；关键协议转换、参数拼接和错误处理添加中文注释。

- **N9：可验证性**
  工具、注册中心、两种协议解析和单轮闭环可以分别通过自动化测试验证；真实终端
  流程可以通过 tmux 观察工具调用与最终答复。

## 不做的事

- **不做 Agent Loop**：只允许一轮工具执行和一次最终续答，不自动反复调用工具。
- **不做并发工具执行**：同一回复中的多个工具按顺序执行；
  `is_concurrency_safe` 仅作为未来调度依据。
- **不做权限确认界面**：Write、Edit、Bash 不弹出批准提示；`read_only` 和
  `destructive` 仅记录元信息。
- **不做命令沙箱**：Bash 从工作目录启动，但不限制命令可以访问的系统范围。
- **不做工具执行中断**：用户不能在执行过程中取消某个工具或当前续答。
- **不做会话持久化**：工具调用和结果只存在于当前会话，退出后不保存。
- **不做可配置工具集**：本章固定注册六个核心工具，不支持用户动态安装、删除或
  关闭工具。
- **不做自定义超时配置**：超时时间和输出上限使用代码内的合理默认值。
- **不做工具搜索和懒加载**：六个工具始终随请求发送，不引入 ToolSearch。
- **不做文件缓存**：每次读取和搜索都以当前磁盘内容为准。
- **不做复杂补丁系统**：改文件仅支持原文唯一匹配替换，不实现 diff、模糊匹配或
  批量补丁。
- **不做多模态结果**：所有工具结果均为文本，不处理图片或其他二进制内容。
- **不展示模型思考内容**：思考增量绝不渲染到 TUI。普通文本对话不保存思考内容；
  仅保留 Anthropic 工具续答协议强制要求原样回灌的隐藏内容块。

## 验收标准

- **AC1（F1、F2）**：注册中心能列出六个工具、按名称找到指定工具，并输出名称、
  描述、参数 Schema 和四类元信息；重复注册和查找未知工具会得到可读错误。
- **AC2（F3：读文件）**：读取指定文本文件时返回带行号的内容；读取不存在、不可读
  或非文本文件时返回结构化错误，程序不崩溃。
- **AC3（F3：写文件）**：可以创建新文件、覆盖已有文件，并在父目录不存在时自动
  创建目录；写入后的磁盘内容与请求一致。
- **AC4（F3：改文件）**：原文唯一匹配时替换成功；匹配零次和多次时文件保持不变，
  结果分别说明实际匹配数。
- **AC5（F3：执行命令）**：普通命令返回 stdout、stderr 和退出码；非零退出和超时
  命令均返回结构化结果，会话不会挂死。
- **AC6（F3：找文件与搜内容）**：glob 能返回匹配文件路径；内容搜索能返回文件、
  行号和命中内容；无匹配时返回明确的空结果。
- **AC7（F4）**：文件类工具访问工作目录内路径成功；使用相对路径或绝对路径尝试
  访问工作目录之外时被拒绝，目标文件不受影响。
- **AC8（F5）**：抓取 Anthropic 和 OpenAI 请求体时，均能看到六个工具定义；模型
  可以根据系统提示词和工具描述正确选择工具。
- **AC9（F6）**：使用被拆分为多个流式片段的工具名称和 JSON 参数进行测试，最终
  能组装出完整调用；一次回复中的多个调用不会互相混淆。Anthropic 开启 thinking
  时，思考内容不出现在 TUI，但续答请求包含原样的隐藏思考内容块。
- **AC10（F7）**：模型一次请求多个工具时，工具按照出现顺序全部执行；其中一个
  失败时，其余工具仍继续执行，所有结果都被回灌。
- **AC11（F8）**：在 tmux 中询问“读取指定文件并总结”，可以观察到模型请求读文件、
  工具返回内容、模型根据真实内容生成最终文字总结。
- **AC12（F8 边界）**：构造需要连续两轮工具的任务，系统只执行第一轮工具；续答
  再次请求工具时不执行，并显示达到单轮上限的提示。
- **AC13（F9）**：Anthropic 使用模拟官方流式事件和请求体的完整协议测试，
  OpenAI/DeepSeek 除同等协议测试外再使用真实 API 与 tmux 执行工具任务；两者都能
  完成定义注入、调用解析、结果回灌和最终续答。
- **AC14（F10）**：TUI 实时显示 `● 工具名(关键参数)` 及成功或失败摘要；长结果不会
  完整铺满界面，工具记录可在 scrollback 中回看。
- **AC15（F11、N4）**：依次触发无效 JSON、缺少参数、未知工具、文件不存在、命令
  非零退出和超时，均不会出现未捕获堆栈；错误后仍可正常发送下一条消息。
- **AC16（N1、N2、N3）**：读取大文件、运行长输出命令和产生大量搜索结果时，执行
  受到超时或数量限制，结果注明截断；等待期间 TUI 计时和滚动保持响应。
- **AC17（N5、N6）**：两种协议下工具展示和错误行为一致；终端、测试输出及错误
  信息中均不出现 API 密钥。
- **AC18（N7、N8、N9）**：Windows 环境下自动化测试、格式检查全部通过；WSL 中
  可通过 tmux 跑通真实端到端场景；核心代码回顾时结构直观，关键复杂逻辑具有
  中文注释。
