# Dragon Code MCP 客户端 Spec

## 背景

Dragon Code 已经具备六个内置工具、Agent Loop、权限系统和模块化 System Prompt，但工具集仍固定在源码中。想让它访问 GitHub、数据库或其他外部服务，目前需要修改 Dragon Code 自身。

ch07 将接入 MCP 客户端，使外部 MCP Server 提供的工具可以通过配置自动加入 Dragon Code。外部工具会被转换为现有的统一工具抽象，因此模型、Agent、TUI 和 LLMClient 不需要区分工具来自内置实现还是外部 Server。

本章遵循当前 MCP SDK 支持的最新协议行为，同时通过 SDK 兼容仍需初始化协商的旧版 Server，不自行维护一套独立协议栈。

## 目标

- **配置驱动**：启动时读取 MCP Server 配置，自动连接、发现并注册工具。
- **双传输支持**：本地 Server 使用 stdio，远程 Server 使用 Streamable HTTP。
- **官方 SDK 承载**：使用官方 MCP SDK 处理通信、协议协商和生命周期，不自行实现 JSON-RPC 协议栈。
- **无感工具适配**：外部工具包装成现有 Tool 抽象，Agent 与 LLMClient 无需区分工具来源。
- **命名空间隔离**：统一使用 `mcp__服务名__工具名`，避免重名并保留来源信息。
- **多 Server 隔离**：并发连接多个 Server；单个失败不影响其他 Server 和六个内置工具。
- **分层配置合并**：用户级配置与项目级配置合并，项目级同名 Server 完整覆盖用户级配置。
- **权限系统复用**：MCP 工具进入现有权限链路，第一次调用交由用户确认。
- **生命周期管理**：缓存成功连接，程序退出时统一关闭会话和 stdio 子进程。
- **既有功能不退化**：不破坏 Agent Loop、流式输出、工具回灌、取消和 TUI 行为。

## 功能需求

- **F1 分层配置加载**：从用户级 `~/.dragon-code/config.yaml` 和项目级 `<项目目录>/.dragon-code/config.yaml` 读取 `mcp_servers`。以 Server 名称为键合并，项目级同名配置完整覆盖用户级配置。没有 MCP 配置时，Dragon Code 仍使用六个内置工具正常启动。

- **F2 Server 配置校验**：Server 必须明确声明 `stdio` 或 `http` 类型。stdio 需要命令，可带参数和环境变量；HTTP 需要 URL，可带请求头。单个 Server 配置错误时跳过该 Server 并给出可读警告，不影响其他 Server。

- **F3 环境变量展开**：stdio 的环境变量和 HTTP 请求头支持 `${VAR}`。如果引用的环境变量不存在，跳过该 Server，并明确显示缺少的变量名；不得把 `${VAR}` 原文或空凭据发送出去。

- **F4 stdio 传输**：本地 Server 通过子进程启动，使用标准输入输出与 Dragon Code 通信。Server 的标准错误可用于显示诊断信息；Dragon Code 退出时应关闭连接并终止对应子进程。

- **F5 Streamable HTTP 传输**：远程 Server 通过 Streamable HTTP 连接，请求携带配置中的 HTTP headers。连接、工具发现和工具调用均由官方 MCP SDK 处理。

- **F6 协议生命周期兼容**：优先遵循当前 MCP SDK 支持的最新协议行为；连接旧版 Server 时，由 SDK 完成必要的初始化协商。Dragon Code 不自行拼装或维护一套独立 JSON-RPC 协议实现。

- **F7 启动期自动发现**：进入 TUI 前并发连接全部 Server，并发现其工具。每个 Server 的连接与工具发现有独立超时；成功的工具注册进工具中心，失败的 Server 只产生警告。即使所有 MCP Server 都失败，Dragon Code 仍可进入 TUI。

- **F8 统一工具适配**：将远端工具的名称、描述、参数 Schema、只读标记和执行入口转换为 Dragon Code 现有工具抽象。Agent、TUI 和 LLMClient 不需要判断工具来自内置实现还是 MCP Server。

- **F9 命名空间隔离**：MCP 工具统一命名为 `mcp__<server>__<tool>`。名称包含模型 API 不接受的字符时，跳过该工具并说明原因；不同 Server 的同名工具不能相互覆盖。

- **F10 工具调用与结果转换**：调用 MCP 工具时，把模型参数交给对应 Server，并将结果转换成现有结构化工具结果。文本内容按原始顺序返回；结构化 JSON 转为便于模型阅读的文本；远端声明失败时保留错误状态和错误内容；图片、音频和资源链接返回“本章暂不支持该结果类型”的结构化提示；连接断开、协议错误和超时均转成结构化错误，不让 Agent Loop 崩溃。

- **F11 权限与执行模式复用**：MCP 工具进入 ch06 权限系统，首次调用需要用户确认，可选择本次、当前会话或永久允许。远端只读标记可用于后续并发安全判断，但不能绕过首次授权。Plan Mode 本章不向模型提供 MCP 工具，`/do` 返回默认模式后才重新提供。

- **F12 连接缓存与退出清理**：成功建立的 Server 会话在 Dragon Code 运行期间复用，不为每次工具调用重新连接。退出时统一关闭 HTTP 会话、stdio 管道和子进程；单个 Server 关闭卡住时不能拖死整个程序。

## 非功能需求

- **N1 失败隔离**：单个 MCP Server 在配置、连接、工具发现、调用或关闭阶段失败，只影响该 Server；不能阻止 Dragon Code 启动，也不能影响其他 MCP Server 和内置工具。
- **N2 超时有界**：每个 Server 的启动连接、每次工具调用和程序退出清理都有内置超时。Server 卡住时必须及时结束等待，不能让 TUI 或 Agent Loop 永久挂起。
- **N3 界面不阻塞**：多个 Server 并发连接、远端工具执行和关闭期间，异步任务不能阻塞界面事件循环。TUI 的状态提示、滚动和取消能力保持正常。
- **N4 安全默认**：配置无法识别、环境变量缺失、工具名称非法、只读标记缺失或结果类型未知时，采用更保守的处理：跳过、要求授权或返回结构化错误，不进行猜测性执行。
- **N5 权限不可绕过**：MCP 工具不能因为来自外部 Server 或声明为只读而绕过首次授权。已有 deny 规则和永久授权规则仍然生效。
- **N6 跨模型协议一致**：MCP 工具能力与 Anthropic、OpenAI 等模型协议解耦。切换 LLMClient 后，工具发现、授权、执行、结果回灌和错误处理行为保持一致。
- **N7 凭据安全**：API Token、HTTP Authorization 和注入子进程的敏感环境变量不得出现在对话区、工具结果、状态栏或普通错误信息中，也不得被写入示例配置。
- **N8 结果体量受控**：远端工具的长文本和大型结构化数据应受现有工具结果上限约束，避免撑爆 TUI 和模型上下文；截断时给出明确标记。
- **N9 退出干净**：程序退出后不残留 stdio 子进程、HTTP 会话或后台异步任务。某个连接无法正常关闭时，应通过退出超时继续完成整体收尾。
- **N10 既有功能不退化**：六个内置工具、Agent Loop、保序执行、流式输出、Token 统计、Plan Mode、权限系统、System Prompt 缓存和用户取消等现有能力保持正常。
- **N11 实现便于学习**：Python 代码尽量采用直观写法，关键生命周期、适配和错误处理位置添加中文注释，避免不必要的高级语法和过度抽象。

## 不做的事

- **非工具能力**：本章只接入 MCP Tools，不实现 Resources、Prompts、Sampling、Roots 等其他 MCP 能力。
- **多模态结果消费**：不在 TUI 中展示 MCP 返回的图片、音频或资源文件，仅返回结构化的“不支持”提示。
- **健康检查与自动重连**：Server 断开后不后台探活、不自动重连；当前调用返回错误，用户可重启 Dragon Code。
- **配置热更新**：运行期间修改配置不会动态连接或移除 Server，需要重启 Dragon Code。
- **MCP 管理界面**：不提供添加、删除、启停、查看 Server 的 TUI 页面或 Slash Command。
- **OAuth 登录流程**：HTTP Server 本章只支持配置静态 headers，不实现浏览器 OAuth 授权、Token 刷新和凭据存储。
- **旧版 SSE 传输**：不单独实现已经被 Streamable HTTP 取代的 HTTP+SSE 客户端；协议初始化兼容交由官方 SDK 处理。
- **Server 自动安装**：Dragon Code 不负责下载或安装 MCP Server；stdio 配置中的命令必须已能在本机运行。
- **网络访问控制**：不限制 HTTP Server 可访问的域名，也不为 MCP Server 增加网络沙箱或流量配额。
- **工具结果持久缓存**：MCP 调用结果不跨轮或跨会话缓存，每次调用都发送给对应 Server。
- **Plan Mode 使用 MCP**：本章计划模式仍只使用内置只读工具，MCP 工具在 `/do` 后才恢复。
- **开发 MCP Server**：本章只实现 Dragon Code 的 MCP Client，不包含自定义 Server 的开发框架。

## 验收标准

- **AC1 配置合并**：用户级和项目级分别配置 MCP Server 后启动 Dragon Code，最终连接两层配置的合集；同名 Server 使用项目级完整配置。完全没有 `mcp_servers` 时仍能正常启动。（F1）
- **AC2 配置错误与变量缺失**：分别构造非法类型、缺少必要字段、缺少 `${VAR}` 的 Server，启动时均显示包含 Server 名和具体原因的警告，只跳过对应 Server，不出现未捕获异常。（F2/F3）
- **AC3 stdio 接入**：配置一个真实 stdio MCP Server 后，Dragon Code 能启动子进程、发现其工具、完成一次调用并把结果交给模型；退出后该子进程不再存在。（F4/F6）
- **AC4 HTTP 接入**：配置一个 Streamable HTTP Server 与自定义请求头后，Dragon Code 能连接、发现工具并完成调用；Server 端能够观察到配置的请求头。（F5/F6）
- **AC5 并发启动与失败隔离**：同时配置一个正常 Server 和一个故障 Server，正常 Server 的工具仍成功注册并可调用。所有 Server 都故障时，TUI 仍能打开并继续使用六个内置工具。（F7）
- **AC6 工具适配与命名**：发现的工具名称均为 `mcp__<server>__<tool>`，描述和参数 Schema 能随模型请求发送；两个 Server 提供同名工具时不会互相覆盖。非法工具名被跳过并显示原因。（F8/F9）
- **AC7 结果转换**：分别调用返回纯文本、结构化 JSON、远端业务错误以及非文本内容的 MCP 工具，文本内容顺序正确、JSON 内容可读、远端错误保留错误状态、非文本内容返回“本章暂不支持”的结构化提示，Agent Loop 均不会崩溃。（F10）
- **AC8 超时与协议错误**：构造调用超时、连接断开和响应格式错误，Dragon Code 将其转成可读的结构化错误回灌给模型，当前会话可继续发送下一条请求。（F10）
- **AC9 权限确认**：首次调用任意 MCP 工具时出现人在回路确认；选择“仅本次”只放行当前调用，选择“本会话”后当前会话不再询问，选择“永久允许”后重启仍能匹配保存的规则。（F11）
- **AC10 Plan Mode**：输入 `/plan` 后发送可能用到 MCP 的任务，请求中不包含 MCP 工具定义；输入 `/do` 后 MCP 工具重新可用并能正常调用。（F11）
- **AC11 会话复用**：连续两次调用同一个 MCP Server 的工具时复用已经建立的连接，不重复启动 stdio 子进程或重复建立完整 Server 会话。（F12）
- **AC12 退出清理**：同时连接 stdio 与 HTTP Server 后退出 Dragon Code，所有连接、子进程和后台任务都完成清理；故意让一个 Server 的关闭过程卡住，程序仍能在退出超时后结束。（F12）
- **AC13 跨模型协议**：分别使用 Anthropic 与 OpenAI LLMClient 运行同一个 MCP 工具任务，工具发现、模型调用、权限确认、结果回灌和最终回复行为一致。（N6）
- **AC14 既有能力不退化**：原有测试全部通过；不配置 MCP 时，内置六工具、多轮 Agent Loop、Plan Mode、权限系统、流式输出和用户取消仍保持原有行为。（N10）
- **AC15 安全与体量控制**：使用长结果和敏感请求头运行 MCP 工具，长结果被截断并带明确标记；对话区、状态栏、普通错误信息和测试输出中均不出现凭据明文。（N7/N8）
- **AC16 端到端**：在 tmux 中启动 Dragon Code，使用真实对话要求模型调用一个 MCP 工具；观察到权限确认、工具行、结果摘要、结果回灌和模型最终答复，并能在完成后继续对话和安全退出。
