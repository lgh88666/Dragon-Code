# Dragon Code ch13 SubAgent 子任务分发 Spec

## 背景

Dragon Code 已经具备完整的单 Agent Loop，并在 ch11 的 fork Skill 中实现了临时子 Agent
雏形。但当前子 Agent 只能由 fork Skill 触发，创建逻辑仍放在 Skill 执行器中，也没有统一
的角色定义、后台任务管理和模型可调用的任务委派入口。

复杂任务继续全部放在主对话中，会带来两个问题：一是搜索结果、工具输出和错误回放持续
污染主上下文；二是长任务会占用当前 Agent Loop，用户无法同时推进其他独立工作。

ch13 引入统一 SubAgent 机制：主 Agent 可以把任务交给独立子 Agent；定义式子 Agent 使用
预定义角色和干净上下文，Fork 子 Agent 继承父对话历史并尽量复用 Prompt Cache。后台任务
完成后向主对话发送通知，但不会自动发起新的模型请求。

## 目标

- **统一委派入口**：提供稳定的 `Agent` 工具，通过可选角色参数选择定义式或 Fork 式子
  Agent。
- **上下文隔离**：子 Agent 独立维护对话、上下文状态、权限临时账本和 Token 用量，避免
  中间过程污染主会话。
- **两种创建模式**：定义式从空白上下文按固定角色工作；Fork 式继承父历史和稳定请求前缀。
- **角色可配置**：使用 Markdown 正文和 YAML frontmatter 声明角色、工具范围、模型、轮次
  和权限模式，并支持多来源覆盖。
- **后台任务管理**：支持显式后台、120 秒自动转后台、`Ctrl+B` 手动转后台和 Fork 强制
  后台，统一追踪状态、结果与用量。
- **安全限制**：通过工具过滤、调用来源标记和 Fork 标记阻止子 Agent 无限嵌套；所有子
  Agent 仍受现有黑名单、路径沙箱、规则和权限模式约束。
- **复用既有能力**：Skill fork 与模型 `Agent` 工具共用轻量 SubAgent 创建底座，不建立
  庞大的通用 `AgentRuntime` 万能类。

## 功能需求

### Agent 工具与角色发现

- **F1 统一 Agent 工具**：主 Agent 始终获得一个名为 `Agent` 的工具。工具接收任务指令、
  一句话任务说明、可选角色名、可选模型覆盖、是否立即后台运行和可选任务名称。角色名非空
  时创建定义式子 Agent；角色名为空时创建 Fork 子 Agent。参数缺失、类型错误或角色不存在
  时返回结构化错误，不中断主 Agent Loop。

- **F2 工具定义稳定**：一个应用会话内，主 Agent 看到的 `Agent` 和任务管理工具定义、顺序
  与参数结构保持不变，不因角色数量、任务状态或某次工具调用而变化。Agent 角色在启动时
  加载，本章不做运行期文件监听。

- **F3 Agent 定义格式**：Agent 定义使用带 YAML frontmatter 的 Markdown 文件。元信息包含
  名称、用途说明、可选工具白名单、可选工具黑名单、可选模型、最大迭代轮数、权限模式和
  是否强制后台；Markdown 正文是伴随子 Agent 整个生命周期的角色指令。名称和说明缺失、
  字段类型错误或正文无效时，该定义不可用并产生可读问题说明。

- **F4 多来源加载与覆盖**：启动时加载项目级、用户级和内置级 Agent 定义，同名时按照
  “项目级 > 用户级 > 内置级”覆盖。加载器预留插件来源入口和最低优先级语义，但本章没有
  真实插件目录时不扫描虚构来源。单个用户或项目定义损坏时跳过该文件并继续启动；内置定义
  损坏视为程序错误并阻止启动。

- **F5 内置角色**：随应用提供 `explore`、`plan`、`verify` 三个角色。`explore` 只读搜索并
  解释代码；`plan` 只读分析并输出计划；`verify` 可以运行验证命令、分析测试结果，但不能
  修改源码。三个定义式角色默认使用 `deepseek-v4-flash`，并允许定义文件或本次调用使用
  Provider 能识别的完整模型名覆盖。

### 子 Agent 创建与运行

- **F6 定义式子 Agent**：指定角色时，从空白 Conversation 启动，把角色正文作为持续有效的
 系统级指令，把任务作为首条用户消息。子 Agent 使用角色限制后的工具集合和独立运行状态，
  模型不再请求工具时自然完成，最终文本作为 `Agent` 工具结果返回；若转入后台则通过任务
  通知和任务工具获取结果。

- **F7 Fork 子 Agent**：未指定角色时，深拷贝父 Agent 当前完整历史，补齐尚未获得结果的
  ToolCall 占位结果，保证消息序列合法，然后追加带 `<fork-boilerplate>` 标记的任务指令。
  Fork 继承主 Agent 当前模型、稳定 System Prompt、对话历史和工具定义前缀，以尽量复用
  Prompt Cache；Fork 始终进入后台。

- **F8 Fork 行为约束**：Fork Boilerplate 明确要求子 Agent 不提问、不请求交互确认、直接
  完成分配任务、不得扩大范围、不得继续创建子 Agent，并输出简短结果。Boilerplate 只存在
  于子 Conversation，不写入主对话历史。

- **F9 跑到底模式**：子 Agent 使用与主 Agent 相同的 ReAct 循环语义，逐轮请求模型、执行
  工具、回灌结果，直到模型返回不含 ToolCall 的最终文本，或触发取消、错误、未知工具阈值
  和角色最大轮次等停止条件。不得维护第二套行为不一致的 Agent Loop。

- **F10 运行状态隔离**：每个子 Agent 拥有独立的 Conversation、上下文管理状态、临时权限
  账本、Skill 激活状态、Token 用量、迭代计数和取消状态。子 Agent 共享应用的文件系统、
  工具实现、稳定规则配置和 Hook 配置；共享部分不得让一个子 Agent 修改另一个 Agent 的
  对话或临时批准状态。

- **F11 模型选择**：定义式子 Agent 在未显式覆盖时使用 `deepseek-v4-flash`；覆盖值按当前
  Provider 的完整模型名称解释。Fork 必须继承父 Agent 当前模型，不允许切换模型，以保持
  请求前缀和缓存复用机会。模型不可用时返回可恢复失败，不影响其他任务。

### 工具过滤与权限

- **F12 多层工具过滤**：子 Agent 工具范围依次受到全局 SubAgent 限制、后台安全白名单、
  角色黑名单和角色白名单约束。后台任务仅能获得允许的内置基础工具以及已通过现有安全层的
  MCP/Skill 工具。最终工具顺序保持原注册顺序。

- **F13 嵌套阻断**：定义式子 Agent 不获得 `Agent` 和后台任务管理工具。Fork 为保持父请求
  的工具定义前缀稳定，可以继续看到相同工具 Schema，但实际调用 `Agent` 或任务管理工具时，
  必须由调用来源标记拒绝；若来源标记丢失，则通过 `<fork-boilerplate>` 历史标记兜底拒绝。
  拒绝以结构化 ToolResult 返回，不导致子 Agent 或主程序崩溃。

- **F14 非交互权限**：子 Agent 不弹出权限确认框。每次工具执行仍先经过危险命令黑名单、
  路径沙箱和持久规则；角色声明的现有权限模式可以在其允许范围内放行操作。最终仍需要询问
  用户的 `Ask` 决策转换成结构化拒绝结果，让子 Agent自行调整。父会话的“仅本次允许”不
  自动继承到子 Agent，项目级和用户级持久规则继续共享。

### 前台、后台与任务管理

- **F15 前台执行**：定义式子 Agent 默认在当前 `Agent` 工具调用中前台执行并返回最终文本。
  前台运行期间 TUI 持续显示子 Agent 的文本、工具调用、结果、迭代和用量，且保持可响应。

- **F16 三种转后台方式**：定义式子 Agent 可以通过 `run_in_background=true` 立即进入后台；
  默认前台任务连续运行 120 秒仍未完成时自动无损移交后台；前台子 Agent 运行期间用户按
  `Ctrl+B` 时手动无损移交后台。移交后不得重新启动或重复执行已经完成的轮次，并立即向
  主 Agent 返回任务 ID。Fork 和 fork Skill 无条件后台运行。

- **F17 后台任务状态**：后台任务至少具有 `queued`、`running`、`completed`、`failed`、
  `cancelled` 状态，并保存任务 ID、可选名称、类型、开始/结束时间、结果或安全错误摘要、
  Token 用量、工具调用次数和最近活动。状态转换必须单向合法；普通失败转换成任务状态，
  不抛出到主 TUI。

- **F18 并发和排队**：同时最多运行三个子 Agent，包含前台和后台任务。超过上限的新任务进入
  `queued` 状态，已有任务结束或取消后按创建顺序启动。排队任务可以被停止，且不会提前
  占用模型请求或执行工具。

- **F19 四个任务工具**：主 Agent 始终获得以下稳定工具：`TaskList` 返回任务摘要列表；
  `TaskGet` 按 ID 返回完整状态、结果和用量；`TaskStop` 请求取消运行中或排队任务；
  `SendMessage` 按任务名称向已完成且仍在本会话内存中的子 Agent 追加任务并复用其独立
  Conversation。未知 ID、重名、忙碌状态或已取消任务返回结构化错误。

- **F20 完成通知**：后台任务进入终态后，TUI 显示简短且可区分的任务通知，并把带
  `<task-notification>` 标签的状态和结果摘要加入主 Agent 下一次请求的动态 reminder。
  reminder 不写入持久对话历史，也不会自动触发新的模型请求。主 Agent 可用 `TaskGet` 获取
  完整结果。

- **F21 取消和退出**：`TaskStop`、主任务取消和程序退出都应尽力取消对应子 Agent、模型流、
  工具协程和排队任务。退出 Dragon Code 时统一清理所有未完成任务；后台任务不跨会话恢复。

### Skill、Hook、协议和界面集成

- **F22 Skill fork 统一**：ch11 的 fork Skill 改为使用同一 SubAgent 创建底座和任务管理器，
  不再自行拼装子 Agent。fork Skill 保留 SKILL.md 的上下文范围、工具白名单、模型和 SOP
  语义，但统一强制后台，先返回任务 ID，完成后通过同一通知和任务查询机制交付结果。

- **F23 Hook 继续生效**：子 Agent 的模型轮次和工具调用继续触发适用的 ch12 Hook；Hook
  失败按现有隔离规则处理。ch12 的 Subagent Hook 动作仍保持安全占位，本章不把 Hook 扩展
  成新的任务创建入口。

- **F24 TUI 展示**：前台子 Agent 事件以可识别的 Agent 名称展示；后台启动、排队、自动/手动
  转后台、完成、失败和取消均产生简短状态行并进入 scrollback。主状态区能提示后台运行和
  排队任务数量，但不显示完整后台内部对话。

- **F25 跨协议一致**：Anthropic 与 OpenAI/兼容端点下，Agent 工具调用、Fork 历史合法化、
  模型覆盖、后台任务、通知、结果查询和取消具有一致的上层行为。协议差异只留在 LLMClient
  适配层。

## 非功能需求

- **N1 缓存稳定性**：主 Agent 工具定义在会话内逐字节稳定。Fork 继承父模型、稳定 System
  Prompt、历史前缀和工具定义顺序；Fork 动态任务只追加在稳定前缀之后。缓存字段可得时应
  能观察到缓存读取，用于验证策略而非承诺特定端点必然命中。

- **N2 界面不阻塞**：前台子 Agent、后台任务、任务通知和队列调度都使用异步路径；模型流、
  工具等待和任务切换期间 TUI 的输入、滚动、计时和状态刷新保持响应。

- **N3 失败隔离**：一个子 Agent 的模型错误、工具错误、超限、取消或异常只影响该任务，
  转换为 `failed`、`cancelled` 或结构化结果；不得让任务异常泄漏并终止主事件循环。

- **N4 历史合法性**：Fork 前缀、占位 ToolResult、动态任务通知、取消和提前终止都不得留下
  悬空 ToolCall、重复 ToolResult 或非法角色顺序。子 Agent 消息不得写入主会话；主会话只
  保存真实工具调用结果和必要的最终用户可见内容。

- **N5 资源有界**：并发上限固定为三个；任务通知和任务结果进入模型前必须有字符上限和
  截断标记；后台状态只在当前会话内存中保存；退出后不残留 asyncio Task、模型流或子进程。

- **N6 文件冲突可见**：本章不提供 Worktree 隔离，多个子 Agent 共享文件系统。允许有副作用
  的角色必须在系统提示和 UI 中说明并发修改可能冲突；不得声称已经解决文件写入冲突。

- **N7 安全和隐私**：任务状态、错误、通知、Agent 定义问题和 TUI 不显示 API Key、授权头、
  环境变量全集、完整异常堆栈或未经截断的大输出。子 Agent 不能绕过黑名单和路径沙箱。

- **N8 兼容性**：ch02–ch12 已有的对话、Agent Loop、权限、MCP、上下文、会话、Skill、命令
  和 Hook 行为不退化；已有测试继续通过。

- **N9 可理解性**：优先使用轻量 SubAgentHost/工厂和简单任务管理器复用创建过程，不引入
  大型依赖容器或万能 Runtime；并发、移交、历史补齐和清理边界添加简短中文注释。

## 不做的事

- 不做 Git Worktree 文件隔离；多个 Agent 的文件写入冲突留给 ch14。
- 不做 Agent Teams、平等 Agent 协作、共享团队任务板或团队消息协议。
- 不做后台任务跨会话持久化、程序重启恢复或远程任务执行。
- 不实现完整插件系统；只保留 Agent 定义插件来源入口。
- 不允许子 Agent 创建孙 Agent，也不支持可配置嵌套深度。
- 不做子 Agent 的交互式权限弹窗或提问用户能力。
- 不让后台任务完成自动唤醒模型；结果在下一次正常请求中注入。
- 不实现 `TaskCreate` 工具，也不接通 ch12 的 Subagent Hook 动作。
- 不为子 Agent 建立独立文件系统、网络沙箱、容器或进程级隔离。
- 不强制子 Agent 输出固定 JSON Schema；最终结果仍为受长度限制的文本。
- 不引入通用 `AgentRuntime` 万能类或完整依赖注入框架。

## 验收标准

- **AC1（F1–F2）**：启动后主 Agent 请求体始终包含稳定的 `Agent`、`TaskList`、`TaskGet`、
  `TaskStop`、`SendMessage` 定义；角色文件增减不改变当前会话工具定义和顺序。
- **AC2（F3–F5）**：合法项目级 Agent 定义可加载并覆盖同名内置定义；损坏的项目定义被跳过
  且不影响启动；内置 `explore`、`plan`、`verify` 均可发现并使用。
- **AC3（F6、F9、F11）**：调用 `explore` 能在空白子上下文中使用
  `deepseek-v4-flash` 完成真实只读任务，模型无 ToolCall 时返回最终文本；主 Conversation
  不包含子 Agent 中间消息。
- **AC4（F7–F8）**：不传角色名时生成 Fork 任务，父历史被深拷贝，悬空 ToolCall 获得占位
  结果，末尾任务带 Fork 标记，Fork 使用父模型并立即返回后台任务 ID。
- **AC5（F10）**：两个子 Agent 同时运行时，对话、Token、ContextManager、Skill 状态和临时
  权限批准互不影响；共享工具与 Hook 配置仍能正常工作。
- **AC6（F12–F13）**：定义式子 Agent 看不到 Agent/任务管理工具；Fork 请求保持稳定工具
  Schema，但实际调用嵌套工具时分别被来源标记和 Fork 标记拦截，主程序继续运行。
- **AC7（F14）**：子 Agent 触发需要询问的 Bash 或写操作时不弹 TUI 审批框，而是收到结构化
  拒绝并可继续调整；已有持久允许规则和角色的合法权限模式仍生效，黑名单与沙箱不可绕过。
- **AC8（F15–F16）**：定义式任务默认前台展示并返回结果；显式后台立即返回任务 ID；测试
  超时阈值下能无重复执行地自动转后台；按 `Ctrl+B` 能无损转后台；Fork 始终后台。
- **AC9（F17–F18）**：同时提交四个可控任务时前三个运行、第四个排队；任一运行任务结束后
  第四个按顺序启动；状态、用量、工具次数和最近活动可观察。
- **AC10（F19）**：四个任务工具分别能列出任务、读取结果和用量、取消运行/排队任务、向已
  完成的命名任务续派工作；非法状态和未知目标返回结构化错误。
- **AC11（F20）**：后台任务完成后 TUI 出现摘要通知，下一次主请求含动态
  `<task-notification>`，持久 Conversation/JSONL 中不含该提醒，并且完成时不会自动调用模型。
- **AC12（F21、N3、N5）**：取消、失败和退出后任务状态正确、主会话可继续，无残留任务、
  模型流或子进程。
- **AC13（F22）**：执行 `/review` 等 fork Skill 时走统一 SubAgent 底座，立即获得后台任务
  ID；完成后可通过通知和 `TaskGet` 取得摘要，Skill 工具范围与 SOP 继续生效。
- **AC14（F23）**：子 Agent 的真实工具调用能触发适用 Hook；一个 Hook 失败不终止子任务，
  Subagent Hook 仍明确报告为安全占位。
- **AC15（F24）**：tmux 中能观察前台 Agent 工具行、后台/排队状态、任务完成或失败通知、
  scrollback 顺序和后台任务计数，界面在整个过程中可输入和滚动。
- **AC16（F25、N8）**：Anthropic 与 OpenAI/兼容端点的自动化协议测试均通过同一 SubAgent
  流程；全量 ch02–ch12 测试无回归。
- **AC17（N1）**：连续 Fork 请求的稳定 System Prompt 与工具定义前缀一致；端点返回缓存
  字段时能观察到缓存读取统计，字段缺失时按零处理且任务正常完成。
- **AC18（N6）**：启动两个具有文件修改能力的后台任务时，UI 明确提示共享文件系统和潜在
  冲突；本章不宣称或模拟 Worktree 隔离。
- **AC19（端到端）**：在 tmux 中启动 Dragon Code，完成“定义式 explore 前台任务 → Fork
  后台任务 → TaskList/TaskGet 查询 → SendMessage 续派 → TaskStop 取消长任务 → fork Skill
  后台完成”的真实流程，并记录实际工具行、状态、结果、通知和退出清理证据。
