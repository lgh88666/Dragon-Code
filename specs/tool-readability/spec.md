# Dragon Code 工具交互可读性优化 Spec

## 背景

Dragon Code 已能显示普通工具、前台子 Agent 工具和后台任务状态，但同一次工具调用通常拆成
“调用行 + 结果行”，并同时使用亮青、紫、绿、黄、红等颜色。Agent Loop 较长或并行子任务较多
时，过程信息会淹没最终回答。

## 目标

- **紧凑工具行**：工具执行中在动态区域临时显示，完成后以一条最终记录进入 scrollback。
- **低饱和配色**：使用接近 Claude Code 的暖橙、柔和灰和暗红，避免大面积高亮。
- **状态符号化**：以 `●`、`✓`、`✗` 区分执行中、成功和失败。
- **任务信息降噪**：正常任务状态隐藏 task ID，完成摘要最多约 80 字。
- **错误保持清晰**：失败使用两行，第二行展示简短原因；完整错误仍回灌模型。
- **过程仍可观察**：前台子 Agent 内部工具继续展示；后台子 Agent 只显示任务状态。

## 功能需求

- F1：主 Agent 工具开始时只进入动态工具区域，不立即写入 scrollback；工具结束后清除动态项并
  写入一条紧凑最终记录。
- F2：成功工具记录包含状态符号、工具名、关键参数和短结果摘要，结果摘要保持单行并限制长度。
- F3：失败、取消和状态未知均有明确符号；真正失败使用暗红两行，第二行显示短原因。
- F4：同时执行多个只读工具时，动态区域按发起顺序展示全部活动项，结束后不残留旧状态。
- F5：前台子 Agent 的文本和内部工具仍可见，内部工具复用相同紧凑格式并带低调的 Agent 标签；
  后台子 Agent 内部事件不写入主 scrollback。
- F6：子 Agent queued/running/转后台/完成状态默认只显示任务名称；完成摘要最多约 80 个终端
  显示宽度（中文约 40 字）；失败
  时显示 task ID 与短原因，方便排查和 TaskGet。
- F7：工具与任务行只使用低饱和暖橙、柔和灰、暗红三类语义颜色，不再使用整行亮青、亮紫、
  亮绿和亮黄。
- F8：主对话 Markdown、Hook、Slash Command、权限弹窗和模型协议行为保持不变。

## 非功能需求

- N1：动态工具刷新不阻塞模型流、TUI 输入和滚动。
- N2：窄终端下文本可自然换行，不因为固定宽度破坏布局。
- N3：所有最终工具记录仍进入 RichLog，可选择、复制和回滚。
- N4：只改变展示，不改变 ToolCall、ToolResult、Conversation 和 Provider 请求格式。
- N5：并发工具完成顺序与 Agent 事件顺序一致，不丢失、不重复。
- N6：代码保持直接，状态集中在少量字典和渲染 helper 中，不引入新 UI 框架或复杂组件树。

## 不做的事

- 不实现工具行折叠、展开和鼠标交互。
- 不更换 RichLog，不重做整个对话布局。
- 不隐藏前台子 Agent 的内部工具。
- 不展示后台子 Agent 的完整内部过程。
- 不修改 Hook、命令、权限审批和主回复的配色。
- 不增加主题配置文件或用户自定义颜色。

## 验收标准

- AC1：较慢工具执行中，动态区域立即出现 `● 工具名 关键参数`；完成后动态项消失，scrollback
  只新增一条成功记录。
- AC2：成功记录为单行紧凑格式，失败记录为状态行加一条短原因，不展示大段结构化 JSON。
- AC3：两个并发只读工具同时出现在动态区域，完成后各自只生成一条最终记录且无残留。
- AC4：前台子 Agent 的内部 Read/Glob/Grep 使用相同格式；后台子 Agent 不刷内部工具行。
- AC5：普通任务状态不含 task ID；完成摘要不超过约 80 个终端显示宽度；失败状态包含 task ID。
- AC6：工具和任务行不再使用 `bold cyan`、`bold magenta`、`bold green` 或亮黄色成功状态。
- AC7：现有 ToolResult 仍完整回灌模型，Agent Loop、多协议、权限和历史行为无回归。
- AC8：Ruff、全量 pytest 和 tmux 真实工具任务全部通过。
