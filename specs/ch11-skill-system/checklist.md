# Dragon Code ch11 Skill 系统 Checklist

> 每一项都必须通过运行代码、测试或观察真实行为验证。开发完成后填写实际证据，不以“应该可以”代替结果。

## Skill 发现与解析

- [ ] **有效 Skill 可以解析**：包含合法 YAML frontmatter 和 Markdown 正文的 `SKILL.md` 能被发现，名称、描述、模式、上下文、工具白名单和 SOP 内容正确。（验证：运行解析单测并查看解析结果。）【AC1】
- [ ] **错误格式可以区分**：缺少名称/描述、非法名称、错误 mode/context、损坏 YAML 和超大文件分别返回带来源路径的可读错误，无未捕获堆栈。（验证：为每类错误各加载一次。）【AC1、N5、N6】
- [ ] **单个损坏不影响其他 Skill**：同一层同时放入一个有效 Skill 和一个损坏 Skill，有效 Skill 仍出现在列表并可执行。（验证：加载混合目录，观察列表和 warning。）【AC2】
- [ ] **三级覆盖正确**：项目级、用户级、内置级存在同名 Skill 时采用项目级；移除项目级后采用用户级，再移除后采用内置级。（验证：三级同名夹具逐层删除后重新加载。）【AC3】
- [ ] **扫描顺序稳定**：相同文件集合连续加载两次，Skill 列表、工具列表和摘要顺序完全一致。（验证：比较两次加载结果文本。）【AC3、N10】

## 渐进式披露与激活

- [ ] **第一阶段只有摘要**：未激活 Skill 时，请求的稳定 System Prompt 只包含 Skill 名称和描述，不包含完整 SOP 或 references 内容。（验证：抓取请求体并搜索 Skill 正文特征句。）【AC4】
- [ ] **摘要跨轮稳定**：Skill 文件未变化时，连续多轮请求的 Skill 摘要逐字节一致。（验证：比较两轮稳定 System Prompt。）【AC4、N1】
- [ ] **自然语言可以自动激活**：用户提出符合某 Skill 描述的任务时，模型可以调用 `LoadSkill`；结果只显示简短激活状态，下一轮请求包含完整 SOP。（验证：真实对话 + 请求记录。）【AC5】
- [ ] **显式命令可以激活**：有效 Skill 自动出现在 `/help` 和 `/` 补全菜单，输入对应命令后进入正确执行模式。（验证：启动 TUI 后查看帮助、补全并执行。）【AC6】
- [ ] **Skill 参数正确替换**：输入 `/commit 只提交 ch11 文件` 后，SOP 中 `$ARGUMENTS` 被替换为完整原始文本，不拆词、不丢空格。（验证：Fake Agent 或请求记录检查动态提醒。）【AC6】
- [ ] **旧命令仍拒绝参数**：`/resume abc` 等原有内置命令仍显示“不接收参数”，并打开原有零参数交互入口。（验证：TUI 输入旧命令和多余参数。）【AC7、N2】
- [ ] **多个 Skill 可以持续激活**：连续激活两个 inline Skill 后，后续每轮都能看到两份 SOP，顺序稳定，重复激活不会重复插入。（验证：连续三轮抓取 reminder。）【AC8】
- [ ] **SOP 不进入持久历史**：普通 Conversation 和会话 JSONL 中只保留真实用户/助手消息，不出现每轮重复 Skill SOP。（验证：运行多轮后检查内存历史和 JSONL。）【AC8、AC25、N4】

## 工具白名单与 inline 执行

- [ ] **inline 工具定义受限**：激活单个 Skill 后，请求中只出现该 Skill 的 allowedTools 与系统工具。（验证：抓取工具定义列表。）【AC9】
- [ ] **伪造调用也不能执行**：模型返回白名单外 ToolCall 时，Agent 返回结构化拒绝结果，不实际运行工具。（验证：Fake Client 伪造 Write/Bash 调用。）【AC9、F10】
- [ ] **多个白名单取并集**：激活两个 Skill 后，可见工具等于两个 allowedTools 的并集，不多也不少。（验证：比较预期集合和请求工具列表。）【AC10】
- [ ] **LoadSkill 始终可见**：即使所有已激活 Skill 的 allowedTools 为空，`LoadSkill` 仍在工具定义中并能继续激活其他 Skill。（验证：空白名单 Skill 后再次 LoadSkill。）【AC10】
- [ ] **inline 不切换模型**：inline Skill 声明 model 时，主 Agent 仍使用当前会话 Provider 和模型。（验证：记录客户端配置和实际请求模型。）【AC11】
- [ ] **inline 复用主上下文**：Skill 执行能读取本会话前文，并继续写入同一合法对话历史。（验证：先提供信息，再运行 inline Skill 引用该信息。）【AC11、N4】

## fork 执行

- [ ] **full 上下文正确**：full fork 得到主会话的完整合法消息副本，但修改子历史不会影响主 Conversation。（验证：比较消息并检查对象相互独立。）【AC12】
- [ ] **recent 上下文正确**：recent fork 只获得最近 5 组完整对话，不截断 ToolCall/ToolResult 配对。（验证：构造超过 5 组且含工具的历史。）【AC12】
- [ ] **none 上下文正确**：none fork 不携带旧主历史，只获得当前 Skill 任务和必要系统上下文。（验证：检查 fork 首轮请求。）【AC12】
- [ ] **fork 过程实时展示**：子 Agent 的文本、工具调用、工具结果、权限请求、进度和错误按真实顺序显示，并标记 Skill 名称。（验证：tmux 执行 `/review` 并观察 scrollback。）【AC13、N3】
- [ ] **fork 只回流摘要**：fork 结束后主历史包含 Skill 触发和最终摘要，不包含完整子对话或中间工具消息。（验证：检查主 Conversation 和 JSONL。）【AC13、N4】
- [ ] **fork 默认继承模型**：未声明 model 的 fork 使用当前 Provider 的当前模型。（验证：记录构造的 fork 客户端配置。）【AC14】
- [ ] **fork 模型覆盖有效**：声明可用 model 时只替换模型名，protocol、base_url、api_key 和 thinking 保持当前 Provider 配置。（验证：Fake Factory 捕获配置。）【AC14】
- [ ] **无效模型可恢复**：fork 指定无效模型时显示可区分错误，主会话不退出且可以继续发送下一条消息。（验证：故意使用无效模型后正常对话。）【AC14、N5】

## 目录型 Skill 与自定义工具

- [ ] **目录型 Skill 能加载**：含 `SKILL.md`、`tool.json`、脚本和 references 的目录能生成 Skill 及新增工具。（验证：加载完整临时目录并查看工具中心。）【AC16】
- [ ] **脚本路径不能逃逸**：脚本路径使用 `..` 或符号链接指向 Skill 目录外时，Skill 在加载阶段被拒绝。（验证：普通越界和符号链接越界各一次。）【AC16、N8】
- [ ] **JSON 管道成功**：脚本从 stdin 收到模型参数 JSON，并从 stdout 返回 JSON 结果，最终形成成功 ToolResult。（验证：运行真实临时 Python 脚本。）【AC17】
- [ ] **脚本失败均结构化**：参数错误、启动失败、非零退出、非法 JSON、超时和过长输出分别返回不同的结构化错误，会话不崩溃。（验证：六类脚本夹具逐个执行。）【AC17、N5、N6】
- [ ] **风险默认值保守**：未配置 annotations 的工具表现为非只读、可能破坏、不可并发，并触发相应权限判断。（验证：检查工具定义和执行决策。）【AC18】
- [ ] **有效注解可以解析**：readOnly/destructive 注解能改变工具元信息和 UI 展示，但不会自动跳过权限规则。（验证：声明只读工具，同时配置明确 deny。）【AC18】
- [ ] **自定义工具严格串行**：同一模型回复请求两个 Skill 自定义工具时，第二个只在第一个完成后启动，结果按模型顺序回灌。（验证：脚本记录开始/结束时间和顺序。）【AC19】

## 权限与安全

- [ ] **危险命令不可绕过**：自定义工具声明的 commandArguments 包含危险命令时，被固定黑名单拒绝；bypassPermissions 也不能放开。（验证：分别在 default 和 bypass 模式执行危险命令。）【AC15、F10】
- [ ] **项目外路径不可绕过**：声明的 pathArguments 指向项目外或经符号链接逃逸时，被路径沙箱拒绝。（验证：读/写路径和符号链接各一次。）【AC15】
- [ ] **规则与模式继续生效**：Skill 工具能被完整工具名 allow/deny 规则匹配；无规则且有副作用时按当前模式得到 Ask/Allow。（验证：用户级、项目级、本地级规则和四种模式测试。）【AC15】
- [ ] **人在回路继续生效**：Ask 时暂停当前 Loop，允许一次、会话允许、永久允许和拒绝均能正确恢复或返回结果。（验证：Fake Approval + 一次真实 TUI 确认。）【AC15】
- [ ] **白名单不替代权限**：工具即使位于 allowedTools 中，也必须继续经过黑名单、沙箱、规则、模式和确认。（验证：白名单内危险工具调用。）【AC15】
- [ ] **安全边界说明真实**：帮助或 Skill 详情明确自定义脚本不是 OS 沙箱，不声称限制脚本内部网络和系统 API。（验证：查看 UI/文档文字。）【N8】
- [ ] **敏感信息不泄漏**：加载错误、脚本 stderr、fork 错误、Skill 详情和对话区均不出现 api_key、Authorization、环境变量全集或 Python 堆栈。（验证：放入哨兵密钥后检索全部输出。）【AC27、N9】

- [ ] **冲突不产生半注册状态**：无效 Skill 不出现在命令、工具或稳定摘要中，其他有效 Skill 的三个视图保持一致。（验证：比较 Manager、CommandRegistry、ToolRegistry。）【AC20、N5】
- [ ] **热更新成功生效**：修改 Skill SOP 后，下一次执行使用新内容，无需重启 Dragon Code。（验证：执行前后使用可辨识文本。）【AC21】
- [ ] **热更新失败可回退**：破坏已加载 Skill 的 frontmatter 后，下一次执行显示 warning 并继续使用上一有效版本。（验证：修改文件后再次执行。）【AC21】
- [ ] **`/skill` 管理完整**：界面可列出 Skill、查看描述/来源/模式/白名单/工具/问题，并可重新扫描。（验证：tmux 操作列表、详情、reload、关闭。）【AC22】

## tmux 端到端场景

- [ ] **场景 1：自然语言自动激活**——在临时项目添加“项目摘要”Skill → 启动 Dragon Code → 请求总结真实文件 → 模型调用 LoadSkill → 下一轮遵循 SOP 调用 Read → 给出最终总结，全程无需用户指定 Skill 名。（验证：tmux scrollback、工具行和最终回复。）【AC5、AC30】
- [ ] **场景 2：显式 inline 与参数**——输入 `/commit 只处理 ch11 文件` → 补全中存在 commit → 参数进入 SOP → Agent 只看到白名单工具 → 权限确认正常 → 最终回复说明实际操作。（验证：tmux scrollback 与 Git 状态。）【AC6、AC9、AC30】
- [ ] **场景 3：review fork**——输入 `/review` → fork 过程实时显示文本和工具行 → 权限请求可操作 → 主会话最终只留下审查摘要 → 再输入普通问题仍可继续。（验证：tmux scrollback、JSONL 与后续回复。）【AC13、AC15、AC24、AC30】
- [ ] **场景 4：目录型自定义工具**——加载带 tool.json 和 Python 脚本的 Skill → 调用工具 → 弹出权限确认 → stdin/stdout JSON 成功 → ToolResult 回灌 → Agent 给出最终答复。（验证：工具行、脚本可观察产物和最终回复。）【AC16–AC19、AC30】
- [ ] **场景 5：热更新与回退**——运行 Skill → 修改 SOP 后再次运行并看到新行为 → 破坏 YAML 后再次运行 → 显示 warning 且继续使用上一版本。（验证：三次输出对比。）【AC21、AC30】

## Checklist 自检

1. AC1–AC30 每条都至少映射到一个可运行或可观察条目。
2. 功能、集成、安全、体量、跨平台、跨协议和回归均有独立检查。
3. 所有条目都写明验证方式，不要求通过逐行阅读源码得出结论。
4. 包含六个完整端到端场景，覆盖自动激活、inline、fork、自定义工具、热更新和取消。
5. tmux 无法可靠证明的缓存字节稳定、消息合法性和双协议请求体由自动化测试提供证据。
