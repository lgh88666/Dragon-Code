# Dragon Code 跨设备协作与开发模式 Spec

## 背景

Dragon Code 已完成 ch02–ch07。代码、章节 Spec 和验收报告已经进入 Git，但长期协作要求仍分散在聊天记录和不同章节中。更换电脑或新建聊天后，Agent 可以获得代码，却不一定知道项目名称转换、Spec 审批、教材参考、代码风格、tmux 验收、源码回顾和 Git 操作等长期约定。

## 目标

- 建立仓库级长期指令，使新 Agent 打开项目后能恢复固定协作规则。
- 建立动态交接文档，记录项目进度、核心结构、验证状态和下一步。
- 完整固化当前 Spec 驱动开发模式，避免跨设备后退化成直接写代码。
- 保留“开发—验收—核心源码回顾—学习笔记”的学习闭环。
- 让教材与 Dragon Code 已批准设计发生差异时有明确处理原则。
- 保证交接文档不包含 API Key 等敏感信息。

## 功能需求

- **F1：仓库级长期规则**：项目根目录提供 Agent 指令文件，集中记录语言、命名、代码风格、安全和工作方式。
- **F2：Spec 开发模式**：任何功能、模块、章节、配置或文档改动都必须经过 `spec.md → plan.md → task.md → checklist.md`。四份文档未全部生成并批准前禁止实现。
- **F3：审批规则**：默认逐阶段审批；用户明确说“后续全部通过”等同义指令时，可以批量批准剩余文档，但四份文档仍必须实际生成并自检。
- **F4：需求澄清方式**：需求阶段一次只问一个问题，优先给出 2–3 个选项并把推荐项放在第一位；设计前提供 2–3 种方案和取舍。
- **F5：教材对齐**：教材及 Vibe Coding 提示词中的 Python 部分是主要参考。发生冲突时，以 Dragon Code 已批准 Spec 和现有代码为准，并向用户解释差异。
- **F6：开发与验收**：批准后按 task 顺序开发，每项先运行验证再报告；完成后运行格式、lint、测试，并在 tmux 中启动 Dragon Code，输入真实对话，逐项核对 checklist。
- **F7：学习闭环**：每章验收后只回顾核心调用链和关键源码，不逐文件讲解；用户指定的重要知识写入 `docs/learning-notes.md`。
- **F8：动态项目交接**：提供项目交接文档，记录已完成章节、当前能力、关键文件、最近验证、未完成事项、新电脑启动步骤和下一步；每章验收后自动更新。
- **F9：Git 规则**：每章验收后自动创建本地提交；只有用户明确要求“推送”时才上传 GitHub。
- **F10：命名与表达**：项目统一称为 Dragon Code；教材或用户后续提示中的 MewCode 自动理解为 Dragon Code。中文回答、中文注释；每项目标优先使用“**概括**：说明”的形式。
- **F11：代码可读性**：Python 代码优先普通类、简单函数和直观分支，避免不必要的高级语法、过度抽象和炫技式实现。
- **F12：跨设备恢复**：交接文档说明 Git 拉取、依赖安装、本地密钥配置和继续聊天的最小步骤；本地密钥不通过 Git 同步。

## 非功能需求

- **N1：可发现性**：长期规则位于仓库根目录，动态交接位于 `docs/`，新 Agent 无需搜索聊天即可找到。
- **N2：职责清晰**：长期规则只记录稳定约定；交接文档只记录会变化的项目状态，避免两份文档相互复制。
- **N3：内容简明**：使用清晰中文、小节和列表，初学者可以直接理解。
- **N4：安全性**：不记录 API Key、Authorization 值、本地密钥文件内容和其他隐私信息。
- **N5：一致性**：文档中的项目阶段、命令和文件路径必须与当前仓库一致。
- **N6：可维护性**：每章更新交接文档时只需修改章节状态、验证证据和下一步，不重写长期规则。

## 不做的事

- 不把完整聊天记录导出或提交到 Git。
- 不提交 `.dragon-code/config.yaml`、`.env` 或权限本地文件。
- 不修改 Dragon Code 功能源码和运行行为。
- 不自动推送 GitHub。
- 不复制飞书教材全文；只记录项目采用的规则和必要的章节对应关系。
- 不在本次补写 ch06/ch07 的完整学习笔记，后续源码回顾时再整理。

## 验收标准

- **AC1（F1/F10/F11）**：根目录存在长期指令文件，明确中文、Dragon Code 命名、简单 Python 和中文注释。
- **AC2（F2/F3/F4）**：长期指令完整写明四文档 HARD GATE、默认审批、显式批量批准和一次一个问题。
- **AC3（F5）**：文档明确教材 Python 为主要参考，已批准 Spec 与现有代码优先，差异必须解释。
- **AC4（F6）**：文档明确 task 验证、完整自动化检查、tmux 真实对话和 checklist 验收。
- **AC5（F7）**：文档明确核心源码回顾范围和学习笔记更新规则。
- **AC6（F8）**：交接文档列出 ch02–ch07、当前架构、核心文件、验证结果、待办和下一步。
- **AC7（F9）**：文档明确验收后本地提交、用户明确要求后才推送。
- **AC8（F12）**：交接文档提供新电脑拉取、`uv sync --locked`、本地配置和继续开发步骤。
- **AC9（N4）**：敏感字符串扫描没有真实密钥；Git 状态不包含被忽略的本地配置。
- **AC10（N1/N2/N5）**：长期规则和动态状态职责没有冲突，文件路径、测试数字与当前仓库一致。
