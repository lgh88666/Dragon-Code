# Dragon Code Agent Loop Spec

## 背景

ch03 已为 Dragon Code 建立统一工具系统。模型能够读取、写入和修改文件，执行命令并搜索项目内容，工具结果也能够回写给模型。

但当前每个用户请求最多只执行一轮工具调用。模型拿到工具结果后，即使发现还需要继续读取文件或修改代码，也不能自主进行下一步。因此，Dragon Code 仍需要用户反复催促，无法独立完成多步骤编程任务。

ch04 将引入 Agent Loop。Dragon Code 会按照 ReAct 范式持续执行“分析任务 → 请求工具 → 观察结果 → 调整行动”，直到任务完成或触发停止条件。

## 目标

- **ReAct 循环**：一轮轮调用 LLM、执行工具、回写结果，直到模型不再请求工具。
- **多种停止条件**：支持自然完成、迭代上限、用户取消、连续请求未知工具和流式响应出错；其中迭代上限作为防止无限循环的兜底安全网。
- **异步事件流**：Agent 输出文本、工具调用、工具结果、Token 用量和迭代进度等事件，使 Agent 与终端界面彻底解耦。
- **流式收集双路**：一边把文本增量实时推送给界面，一边收集完整响应及工具调用，供 Agent 判断下一步。
- **保序分批并发**：一次回复中的多个工具调用按照安全性分批；连续的并发安全工具同时执行，有副作用的工具串行执行，并保持模型给出的相对顺序。
- **Plan Mode 两段式**：`/plan` 进入持续的只读计划模式；`/do` 恢复全部工具，并立即执行对话中的最新计划。

## 功能需求

- **F1：ReAct 主循环编排**
  替换 ch03 的单轮闭环。每轮携带工具定义和完整历史请求模型，同时收集流式响应。模型请求工具时，执行工具并将结果回写历史，然后进入下一轮；模型返回不含工具调用的最终文本时，循环自然结束。续答中的工具调用不再被丢弃。

- **F2：多种停止条件**
  Agent Loop 在以下任一条件下停止，并向界面发出明确事件：
  1. 模型回复不包含工具调用，自然完成。
  2. 达到 50 次模型迭代上限。
  3. 用户按 `Esc` 取消当前任务。
  4. 连续 3 次迭代只请求注册中心不存在的工具。
  5. Provider 流式响应出错或未完整结束。
  单个已注册工具执行失败不终止循环，其结构化错误继续回写给模型。

- **F3：统一异步事件流**
  Agent 对外只输出事件，界面只消费事件，不参与循环判断和工具调度。事件覆盖：
  - 文本增量
  - 工具调用开始
  - 工具调用结束及结构化结果
  - Token 用量
  - 迭代进度
  - 任务完成
  - 用户取消
  - 达到限制
  - 运行错误

- **F4：流式收集双路**
  每轮响应同时走两条路径：正文增量实时进入事件流，供界面显示；内部同步收集完整正文、工具调用和协议要求保留的隐藏内容，供 Agent 判断下一步。工具名称和 JSON 参数即使分片到达，也必须被组装成完整调用。

- **F5：保序分批并发执行**
  按模型给出的顺序扫描本轮工具调用：
  - 连续且声明为并发安全的工具组成一个并发批次。
  - 有副作用或不具备并发安全性的工具分别组成单独批次，串行执行。
  - 后续批次等待前一批次全部结束。
  - 并发批次的结果按照原始工具调用顺序回写。
  每个工具继续使用 ch03 已有的独立超时和结构化错误机制。

- **F6：结果回写与历史一致性**
  每个完整迭代产生的助手回复和工具结果按顺序写入历史，下一轮请求携带完整历史。工具调用与结果必须一一对应，协议角色和消息顺序保持合法。任务提前停止后，会话仍可继续使用。

- **F7：用户取消与历史收尾**
  Agent 运行期间按 `Esc` 取消当前任务，不退出 Dragon Code。系统根据取消发生的阶段处理历史：
  1. 模型响应尚未完整结束：丢弃当前不完整响应，保留此前完成的迭代。
  2. 模型响应已经完整、工具正在执行：保留助手工具调用，并为每个调用提供结果。
     - 已完成工具保存真实结果。
     - 尚未开始的工具返回结构化“已取消”结果。
     - 已经开始但无法确认是否停止的工具返回“已请求取消，最终状态未知”。
  3. 本轮工具已经全部完成：正常保存全部结果，只阻止下一次模型请求。
  取消后恢复输入状态。系统不自动撤销已经发生的文件修改或命令操作。

- **F8：取消传播**
  收到取消请求后，系统停止创建新的模型请求和工具批次，并尝试取消当前流式请求及正在执行的工具。取消属于尽力而为：对于无法立即停止的底层操作，必须明确报告结果状态未知，不得错误宣称操作一定没有发生。

- **F9：Token 用量统计**
  Provider 从每次流式响应中提取输入和输出 Token 用量，通过事件交给上层。一次 Agent 任务包含多轮模型请求时，对各轮用量进行累计；任务结束时显示本次任务的累计 Token 和总耗时。兼容端点不提供用量时显示“用量未知”，不影响任务执行。

- **F10：迭代进度展示**
  每次模型迭代开始时产生进度事件，包含当前次数和最大次数。流式期间界面动态显示类似 `Agent working… 3/50` 的状态。

- **F11：持续 Plan Mode**
  输入 `/plan` 或 `/plan 任务内容` 后切换到 Plan Mode：
  - 带任务内容时，立即开始规划。
  - 不带任务内容时，只切换模式并等待下一条用户请求。
  - 模式期间只向模型提供 `Read`、`Glob`、`Grep`。
  - 每次请求都注入计划模式约束，要求模型只探索和完善方案，不修改项目。
  - 模型自然结束一次回复后仍保持 Plan Mode，用户可以继续提问、补充要求或调整计划。
  - 计划保存在当前对话上下文中，不单独写入文件。

- **F12：`/do` 切回执行模式**
  Plan Mode 中输入 `/do` 后：
  - 恢复全部六个工具。
  - 切换到持续的 Default Mode。
  - 自动发送一条内部执行指令，让模型根据上文最终计划开始 Agent Loop。
  - 后续普通消息继续使用 Default Mode，除非用户再次输入 `/plan`。
  尚未形成有效计划或当前不处于 Plan Mode 时输入 `/do`，系统显示清晰提示，不发起执行请求。

- **F13：跨协议一致**
  Anthropic 与 OpenAI/DeepSeek 兼容协议均支持完整 Agent Loop、流式收集、Token 用量提取、工具分批执行和停止条件。Agent 与 TUI 不依赖具体协议格式。

- **F14：TUI 实时呈现**
  界面实时展示模型文本、工具调用、工具结果摘要和迭代进度。任务结束后显示总耗时与累计 Token；取消、迭代上限、未知工具停止和流式错误采用可区分样式，并写入 scrollback 历史。

## 非功能需求

- **N1：工具执行超时**
  每个工具继续使用 ch03 内置的 30 秒独立超时，本章不提供配置入口。超时转换为结构化结果回写给模型，不中断整个 Agent Loop。

- **N2：界面不阻塞**
  多轮模型请求、工具执行和并发批次运行期间，界面保持响应；文本、spinner、迭代进度和计时持续刷新，不得冻结。

- **N3：scrollback 顺序正确**
  跨迭代产生的前置文本、工具调用、结果摘要和最终答复按照真实发生顺序进入 scrollback。并发批次中的工具行和结果按照模型给出的调用顺序展示，不因实际完成顺序不同而交错。

- **N4：历史与协议合法**
  无论自然完成、取消、达到限制还是发生错误，已提交历史中的工具调用都必须具有对应结果。Anthropic 与 OpenAI/DeepSeek 请求历史均符合各自的角色顺序和工具配对要求。

- **N5：循环安全**
  50 次迭代上限与连续 3 轮未知工具限制由程序强制执行。达到停止条件后不得继续发起模型请求或创建新工具批次。

- **N6：取消及时且无任务泄漏**
  用户按 `Esc` 后尽快停止后续迭代，并对当前网络流和工具执行进行尽力取消。循环结束后不得残留仍在调度的异步任务、未关闭的事件通道或持续更新界面的后台工作。

- **N7：并发安全**
  并发批次中的工具互不修改共享结果，单个任务异常不破坏其他任务。结果收集不得发生数据竞争，并且最终按照原始调用顺序输出。

- **N8：流式实时性**
  文本增量到达后应尽快进入界面，不等待本轮完整响应结束。内部完整响应收集不得明显延迟实时输出。

- **N9：错误隔离**
  工具超时、工具异常、未知工具、无效参数、Provider 流错误和 Token 用量缺失，都不得形成未捕获异常或导致 Dragon Code 退出。

- **N10：跨协议一致**
  Anthropic 与 OpenAI/DeepSeek 兼容协议的循环规则、停止行为、取消收尾、事件顺序和界面体验保持一致。

- **N11：Token 用量兼容**
  Provider 返回用量时准确累计输入和输出 Token；兼容端点没有提供完整用量时显示“用量未知”，不伪造数值，也不影响任务继续。

- **N12：结果体量受控**
  沿用 ch03 的工具级行数、字符数和结果数量限制，并明确标记截断。多轮运行不得把单次超长结果完整铺满界面或直接撑爆模型上下文。

- **N13：密钥安全**
  API 密钥不得出现在事件、工具结果、错误信息、scrollback、终端输出或自动化测试结果中。

- **N14：代码可读性与质量**
  优先使用普通类、简单函数和直观分支，避免不必要的高级语法与过度抽象。Agent 循环、流式双路收集、并发分批、取消收尾和模式切换添加中文注释。代码应通过项目规定的格式和静态检查，具体命令写入 checklist.md。

- **N15：可验证性**
  循环、事件顺序、五类停止条件、并发调度、取消历史和 Plan Mode 可以分别自动化测试；完整流程能够使用 tmux 做端到端验收。

## 不做的事

- **不做权限系统**：Write、Edit、Bash 等工具本章不弹出授权确认；工具权限矩阵留到后续章节。
- **不做交互式操作审批**：Agent 执行过程中不会逐个询问用户是否允许修改文件或运行命令。
- **不做执行沙箱**：不新增命令隔离、系统资源限制或更严格的路径白名单，继续沿用 ch03 的工具边界。
- **不做上下文压缩**：Agent 多轮产生的历史不摘要、不裁剪；超长上下文管理留到后续章节。
- **不做自动恢复和重试**：Provider 流出错后结束当前任务，不自动重连、退避或继续未完成循环。
- **不做操作回滚**：用户取消、达到上限或发生错误时，不自动撤销已经写入的文件或已经执行的命令。
- **不保证强制终止所有底层操作**：取消采用尽力而为；已经进入不可中断阶段的操作可能完成，并以“状态未知”明确反馈。
- **不做跨进程恢复**：Agent Loop、当前模式、计划和对话历史都只存在于本次运行，退出后不保存。
- **不做计划文件**：Plan Mode 的计划只保存在对话中，不创建或维护独立计划文件。
- **不在 Plan Mode 提供 Bash**：即使是只读命令也不开放；计划阶段固定只提供 Read、Glob、Grep。
- **不做可配置循环参数**：50 次迭代上限、连续 3 轮未知工具阈值和 30 秒工具超时使用内置值。
- **不做复杂任务依赖调度**：只按照模型给出的工具顺序和并发安全元信息分批，不分析工具参数之间的数据依赖。
- **不做跨任务并发**：同一时间只运行一个用户任务；运行期间不接受新的普通消息提交。
- **不做多 Agent 或子 Agent**：本章只有一个 Agent Loop，不拆分任务给多个 Agent。
- **不做动态工具集**：Default Mode 固定使用 ch03 的六个工具，Plan Mode 固定使用三个只读工具。
- **不做费用计算**：只统计 Provider 返回的 Token 用量，不换算 API 费用。
- **不新增可扩展 Slash 命令体系**：本章只增加 `/plan` 和 `/do`，不实现通用命令注册框架。

## 验收标准

- **AC1：多轮自动执行**
  提交需要连续多步工具的任务，例如“读取 `specs/ch03-tool-system/spec.md`，再根据内容创建摘要文件”。Agent 自动完成多轮工具调用和结果回写；模型最终返回不含工具调用的文本后结束，全程不需要用户催促。（F1）

- **AC2：自然完成**
  模型直接给出不含工具调用的纯文本时，循环立即停止，该文本成为最终答复，不再请求模型。（F2）

- **AC3：迭代上限兜底**
  模拟模型持续请求工具的情况，达到 50 次迭代后停止并提示，不产生第 51 次请求。自动化测试可以注入较小上限加速验证，但用户运行时固定为 50。（F2）

- **AC4：连续未知工具停止**
  模型连续三轮只请求不存在的工具时停止并提示；中间出现包含已注册工具的迭代时，连续计数重置。（F2）

- **AC5：流式错误恢复**
  Provider 流式响应出错或未完整结束时停止当前任务，显示错误，程序不退出；输入状态恢复后可以继续正常对话。（F2）

- **AC6：事件流完备**
  一次多轮任务产生文本增量、工具开始、工具结束、Token 用量、迭代进度、完成或错误等事件；测试界面只消费这些事件即可完成渲染，不直接操作 Agent 内部逻辑。（F3）

- **AC7：流式收集双路**
  文本增量实时显示的同时，内部正确收集完整正文和工具调用；分片到达的工具名称及 JSON 参数最终能够完整拼接，并用于下一轮判断。（F4）

- **AC8：保序分批并发**
  给定 `Read A → Glob B → Edit C → Read D`，Read A 与 Glob B 并发执行，Edit C 单独串行，随后执行 Read D；工具结果按照 A、B、C、D 的原始顺序展示和回写。（F5）

- **AC9：历史一致**
  正常多轮中的助手工具调用与工具结果按顺序进入历史。自然完成、达到上限、未知工具停止、取消和流式错误后，历史仍符合当前协议要求，不存在悬空工具调用，下一条正常消息不会因历史非法而请求失败。（F6）

- **AC10：响应阶段取消**
  模型响应尚未完整结束时按 `Esc`，当前部分响应被丢弃，此前完整迭代继续保留；Agent 回到空闲状态但不退出，用户可以继续输入。（F7、F8）

- **AC11：工具阶段取消**
  多个工具执行过程中按 `Esc`：
  - 已完成工具保留真实结果。
  - 未开始工具得到结构化“已取消”结果。
  - 无法确认是否停止的工具得到“最终状态未知”结果。
  - 所有已提交工具调用都有对应结果。
  - 不再启动下一迭代。
  - 没有残留的 Agent 调度任务。（F6、F7、F8）

- **AC12：用量与进度展示**
  流式期间动态区显示当前迭代轮次，例如 `3/50`；任务结束时显示本次 Agent 任务累计的输入 Token、输出 Token、总 Token 和耗时。Provider 未提供用量时显示“用量未知”。（F9、F10）

- **AC13：持续 Plan Mode**
  输入 `/plan 任务内容` 后进入 Plan Mode，发给模型的工具定义只有 Read、Glob、Grep。模型完成第一版计划后仍保持该模式；继续提出修改要求时仍只能使用三个只读工具，且不会创建计划文件。（F11）

- **AC14：`/do` 执行计划**
  Plan Mode 中输入 `/do` 后恢复六个工具，并立即根据上文计划启动 Agent Loop；执行完成后继续处于 Default Mode。没有有效计划或不处于 Plan Mode 时输入 `/do`，只显示提示，不请求模型。（F12）

- **AC15：跨协议一致**
  分别使用 Anthropic 与 OpenAI/DeepSeek 兼容配置运行同一个多轮任务，两者都能完成工具触发、分批执行、结果回写、用量提取、取消和最终收尾，上层事件行为一致。（F13）

- **AC16：真实终端场景**
  在 tmux 中运行多轮工具任务，文本、spinner、计时和迭代进度持续更新，界面不冻结；工具行、结果和最终答复按顺序进入 scrollback。长结果正确截断，错误可恢复，终端及测试输出中不出现 API 密钥。（F14、N2、N3、N12、N13）
