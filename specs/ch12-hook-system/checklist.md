# Hook 生命周期自动化系统 Checklist

> 每一项都必须通过运行测试、执行命令或观察真实行为验证；不得仅凭阅读源码判定通过。

## 配置与匹配

- [x] 项目级 `.dragon-code/hooks.yaml` 与用户级 `~/.dragon-code/hooks.yaml` 可同时加载；同名 Hook 由项目级覆盖，加载顺序稳定。（验证：运行配置加载测试，并通过 `/hooks` 对照名称、来源与顺序）(AC1/F1)
- [x] 无 Hook 配置时 Dragon Code 保持原有行为并可正常启动。（验证：移除测试配置后启动应用并提交一轮普通对话）(AC1/F1)
- [x] 非法 YAML、缺少字段、未知事件、未知动作、非法正则和冲突控制项只跳过对应 Hook，并产生可读问题信息。（验证：逐类构造无效配置，运行配置测试并观察程序仍可启动）(AC1/F2)
- [x] 精确、glob、正则和取反匹配均能区分命中与不命中。（验证：运行统一匹配器参数化测试）(AC2/F3)
- [x] 原有权限规则 `Bash(git *)` 的匹配行为不变。（验证：运行原权限规则与权限引擎回归测试）(AC2/N4)
- [x] 条件可读取嵌套上下文字段，`all_of` 和 `any_of` 行为正确；缺失字段按不匹配处理。（验证：运行条件解析与求值测试）(AC3/F4)
- [x] 条件组嵌套或混用 `all_of`、`any_of` 时在加载期被拒绝。（验证：加载对应反例配置并检查可读问题信息）(AC3/F4)

## 动作与执行控制

- [x] Shell 动作在项目工作目录运行，可收到经过脱敏的完整 HookContext JSON 和安全 `DRAGON_*` 环境变量，并返回 stdout、stderr 与退出码。（验证：运行 Shell 动作测试，检查 cwd、stdin、环境变量与结果）(AC5/F7)
- [x] Shell 命令本身保持静态，不把 `args.path` 等不可信字段直接拼接进命令行。（验证：传入含 shell 元字符的路径，确认它仅作为上下文数据出现且没有执行附加命令）(F6/F7/N6)
- [x] Shell 动作无需再次弹出权限确认，且退出码 `2` 在可阻塞事件中被解释为拒绝，stderr 成为拒绝原因。（验证：运行拦截动作测试并观察无权限弹窗）(AC5/AC6/F8)
- [x] Prompt 动作生成 `<hook-notification>`，只在下一次模型请求注入一次，随后清除且不写入 JSONL 会话历史。（验证：连续构造两次请求并检查请求体与会话文件）(AC8/F9/N5)
- [x] HTTP 动作正确发送方法、地址、请求头和模板化请求体；缺少模板字段时返回可读失败。（验证：使用本地 HTTP 测试服务检查收到的请求）(AC9/F10)
- [x] 同步前置 HTTP Hook 收到 `{"block": true, "reason": "..."}` 时阻止当前操作。（验证：本地服务返回结构化拒绝并检查真实操作未发生）(AC9/F10)
- [x] Subagent 动作可被加载和触发，但只返回“尚未实现”的占位结果，不创建子 Agent、不终止会话。（验证：运行占位动作测试后继续正常请求）(AC10/F11)
- [x] `only_once` 在同一会话最多执行一次，新建或恢复会话后重新计算。（验证：同一会话触发两次，再切换会话触发一次）(AC11/F12)
- [x] 非阻塞 Hook 可异步执行且不拖住主流程；可阻塞 Hook 配置为异步时在加载期被拒绝。（验证：配置延迟动作并测量主流程返回时间，同时检查冲突配置问题）(AC11/F12)
- [x] 所有外部动作受超时限制；超时后产生可读结果，Agent Loop 和 TUI 仍可继续。（验证：分别触发超时 Shell 与 HTTP 动作，再发送正常消息）(AC11/AC12/N1/N2)

## 生命周期与拦截

- [x] 11 个事件都在规定时机触发：`SessionStart`、`SessionEnd`、`SessionResume`、`UserPromptSubmit`、`Stop`、`PreUserMessage`、`PreToolUse`、`PostToolUse`、`PreCompact`、`PostCompact`、`Notification`。（验证：运行生命周期集成测试并对照事件顺序记录）(AC4/F5)
- [x] 每个事件都包含事件名、会话 ID、工作目录和当前模式；专用事件额外包含约定的输入、工具、结果、压缩、Token 或错误字段。（验证：捕获 11 类 HookContext 并逐项断言）(AC4/F6)
- [x] `UserPromptSubmit` 被拒绝时消息不写入历史，界面显示 Hook 名称与原因，原输入保留并可编辑后重新提交。（验证：在 TUI 中触发拒绝、修改文本、再次提交）(AC7/F8)
- [x] `PreToolUse` 在权限判断和真实工具执行之前运行；拒绝后文件或命令没有实际变化，模型收到 `hook_denied` 结构化结果。（验证：拦截写文件操作并检查磁盘、事件顺序和回灌内容）(AC6/F8)
- [x] 同一事件的同步 Hook 按项目级在前、用户级在后的稳定顺序运行；首个拒绝后不再执行剩余同步 Hook。（验证：用带序号输出的多 Hook 配置检查执行记录）(F8/N3)
- [x] `PostToolUse` 对成功、失败、权限拒绝、Hook 拒绝、超时和取消后的最终工具结果均可触发。（验证：逐类构造工具结果并检查事件记录）(F5/F6)
- [x] 手动压缩与自动压缩都按 `PreCompact → 压缩 → PostCompact` 的顺序触发。（验证：运行压缩集成测试并检查事件顺序）(F5)
- [x] 会话新建、清空、恢复和退出时，Session Hook 顺序符合设计且 `only_once` 状态不会串到其他会话。（验证：运行会话生命周期测试）(F5/F12)

## 故障隔离、历史与清理

- [x] Shell 非零退出、HTTP 连接失败、HTTP 超时、模板字段缺失和动作内部异常均转成可读结果，不出现未捕获堆栈。（验证：运行四类失败测试并继续一轮正常对话）(AC12/F13)
- [x] 一个非拦截 Hook 失败不妨碍同事件后续 Hook，也不终止 Agent Loop。（验证：先配置失败动作、再配置成功动作，确认后者仍执行）(F13)
- [x] Hook 提醒、拦截、超时和异步结果不制造悬空工具调用、非法角色顺序或损坏 JSONL；之后可继续请求并恢复会话。（验证：运行历史一致性测试并实际恢复会话）(AC8/AC15/F16/N5)
- [x] API Key、Authorization、密码及敏感环境变量不出现在 Hook 上下文、`/hooks`、错误提示、TUI 或测试日志中。（验证：使用哨兵秘密值运行脱敏测试并检索全部输出）(AC14/F6/N6)
- [x] 退出时异步 Hook 在有限时间内完成或取消，不残留 asyncio 任务、Shell 子进程或 HTTP 请求。（验证：启动长耗时异步 Hook 后退出，检查任务与进程）(AC13/F14/N7)

## 端到端场景

- [x] 场景 1（写后自动动作）：在项目 Hook 配置中为 `PostToolUse` 配置只匹配写文件的 Shell 动作 → tmux 启动 Dragon Code → 请求 Agent 修改一个 Python 测试文件 → 工具成功后自动执行格式化/标记动作 → TUI 显示 Hook 结果，磁盘内容符合预期，且没有额外权限弹窗。(AC5/AC16)
- [x] 场景 2（危险操作前置拦截）：配置同步 `PreToolUse` Hook 拒绝指定路径写入 → 请求 Agent 修改该路径 → TUI 显示 Hook 名称和拒绝原因 → 文件保持不变 → 模型收到结构化错误并调整答复 → 会话仍可继续。(AC6/AC16)
- [x] 场景 3（输入拦截恢复）：配置 `UserPromptSubmit` Hook 拒绝指定文本 → 提交后消息不进入历史且输入仍在 → 修改为允许文本后正常提交并收到回复。(AC7)
- [x] 场景 4（退出清理）：触发长耗时异步 Hook 后退出 Dragon Code → tmux 会话结束 → 检查无残留 Hook 子进程或后台任务，终端状态正常。(AC13)
