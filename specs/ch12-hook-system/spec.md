# Hook 生命周期自动化系统 Spec

## 背景

Dragon Code 已具备工具调用、Agent Loop、权限控制、上下文管理、会话与记忆、斜杠命令和 Skill 等能力。现有扩展大多需要用户主动发起命令，或者由模型自行决定是否调用工具，缺少在固定生命周期节点自动执行规则的机制。

本章为 Dragon Code 增加 Hook 系统。用户可通过声明式配置，在会话启动、用户提交、模型请求、工具执行、上下文压缩和通知等节点自动执行动作；其中部分前置 Hook 可以拒绝危险操作。Hook 的失败不会破坏 Agent Loop，既有功能与历史结构保持兼容。

## 目标

- **生命周期自动化**：覆盖会话、用户输入、模型请求、工具执行、上下文压缩和通知相关的 11 个固定事件。
- **声明式配置**：从项目级和用户级 YAML 文件加载 Hook，并按照确定规则合并与校验。
- **统一匹配语义**：提供精确、glob、正则和取反匹配，并让权限规则复用同一套匹配能力。
- **前置操作拦截**：允许同步 Hook 在用户消息进入历史或工具真正执行前拒绝操作，并返回清晰原因。
- **多种自动动作**：支持 shell、提示注入、HTTP 和预留的子 Agent 四类动作。
- **执行控制**：支持仅执行一次、异步执行和超时限制，避免 Hook 阻塞主流程。
- **故障隔离**：单个 Hook 配置错误、执行失败或超时不导致程序崩溃，也不破坏后续会话。
- **可观测性**：通过只读 `/hooks` 命令查看已加载 Hook 的关键信息。
- **保持兼容**：不削弱此前章节的 Agent Loop、权限、工具、上下文、会话、命令和 Skill 能力。

## 功能需求

### F1：Hook 配置加载与合并

- 从项目级 `.dragon-code/hooks.yaml` 和用户级 `~/.dragon-code/hooks.yaml` 加载 Hook 配置。
- 两层配置采用追加合并，使项目与用户 Hook 可以同时生效。
- Hook 名称重复时，项目级配置优先；同名用户级 Hook 被跳过，并产生可读警告。
- 未配置 Hook 时，Dragon Code 按原有行为正常启动和运行。

### F2：配置校验与降级

- 每条 Hook 至少声明名称、触发事件和动作。
- 无效 YAML、缺失必要字段、未知事件、未知动作、非法匹配表达式或互相冲突的控制选项，均产生可读错误。
- 单条 Hook 无效时只跳过该条，不影响其他有效 Hook，也不导致程序崩溃。

### F3：统一匹配能力

- 支持四种匹配方式：精确匹配、glob 匹配、正则匹配和取反匹配。
- Hook 与权限规则使用一致的匹配语义。
- 已有权限配置保持兼容，例如 `Bash(git *)` 仍按 glob 规则匹配。
- 非法正则表达式在加载期被识别并跳过，不推迟到实际操作时才崩溃。

### F4：条件判断

- Hook 可依据事件上下文中的嵌套字段决定是否触发，例如工具名称、路径、命令、模式或执行结果。
- 条件支持顶层 `all_of` 或 `any_of`，一条 Hook 只能选择其中一种。
- 本章不支持条件组嵌套，也不允许在同一条件中混用 `all_of` 与 `any_of`。
- 字段路径不存在时按不匹配处理，不抛出未捕获异常。

### F5：生命周期事件

系统支持以下 11 个事件，并在对应时机触发：

1. `SessionStart`：新会话已准备完成后。
2. `SessionEnd`：会话关闭或切换之前。
3. `SessionResume`：历史会话恢复完成后。
4. `UserPromptSubmit`：普通用户消息写入历史之前；该事件可阻止提交。
5. `Stop`：Agent 自然完成本轮任务后。
6. `PreUserMessage`：每次向模型发起请求之前。
7. `PreToolUse`：工具执行和权限判断之前；该事件可阻止工具执行。
8. `PostToolUse`：工具成功或失败并形成结果之后。
9. `PreCompact`：上下文压缩开始之前。
10. `PostCompact`：上下文压缩完成之后。
11. `Notification`：出现权限询问、流式错误等需要通知用户的情况时。

### F6：事件上下文

- 每个事件都提供事件名称、会话标识、当前工作目录和当前模式等通用信息。
- 不同事件按需提供工具名称、工具参数、工具结果、用户输入、压缩原因、Token 信息或错误信息等专用字段。
- Hook 只能读取当前事件允许提供的信息，不应暴露 API 密钥、授权头或敏感环境变量。

### F7：Shell 动作

- Shell 动作在当前项目工作目录中执行，并可将事件上下文中的字段代入命令模板。
- 执行结果包含标准输出、标准错误和退出码，并受超时限制。
- Hook 配置被视为用户主动授权的自动化规则，执行 Shell 动作时不再弹出权限确认。

### F8：同步拦截

- 同步 `PreToolUse` 和 `UserPromptSubmit` Hook 可以拒绝当前操作。
- Shell 动作以退出码 `2` 表示拒绝，标准错误内容作为拒绝原因。
- 工具被拒绝时不执行真实工具，并向模型回灌结构化错误结果，使其可以调整方案。
- 用户输入被拒绝时不写入历史，界面显示拒绝原因，并保留原输入供用户修改。
- 同一事件的同步 Hook 按确定顺序运行，首个拒绝结果出现后停止执行该事件剩余 Hook。

### F9：提示注入动作

- Prompt 动作把生成的内容包装为 `<hook-notification>` 补充提醒，在下一次模型请求时注入。
- 提示模板可引用当前事件上下文字段。
- 提醒不写入持久会话历史，使用一次后清除，不破坏消息角色交替和工具调用配对。

### F10：HTTP 动作

- HTTP 动作支持声明请求方法、地址、请求头、请求体模板和超时时间。
- 请求内容可引用事件上下文字段。
- 同步前置事件可根据 HTTP 服务返回的结构化拒绝结果阻止当前操作。
- HTTP 动作同样视为已由 Hook 配置授权，不再弹出权限确认。

### F11：子 Agent 动作占位

- 配置可声明子 Agent 动作，以便后续章节保持配置兼容。
- 本章只校验和识别该动作；触发时给出明确的“尚未实现”结果，不真正创建子 Agent。
- 占位动作不会阻断 Agent Loop 或导致程序崩溃。

### F12：执行控制

- `only_once` 使一条 Hook 在当前会话中最多执行一次；新建或恢复会话时重新计算本会话状态。
- `async` 使非拦截型 Hook 在后台运行，不等待其完成即可继续主流程。
- 能阻止操作的 Hook 不允许异步执行，冲突配置在加载期被拒绝。
- 每条 Hook 都受超时限制，并可在配置中覆盖合理的默认时长。

### F13：失败隔离

- Shell 非零退出、模板字段缺失、HTTP 请求失败、动作超时和动作内部异常均转成可读结果。
- 非拦截型 Hook 的失败只产生提示，不终止当前 Agent Loop。
- 一个 Hook 失败不影响同一事件中其他可继续执行的 Hook，也不影响其他事件。

### F14：后台任务生命周期

- 系统跟踪所有异步 Hook 任务。
- 会话关闭或程序退出时，在有限时间内等待或取消剩余任务。
- 退出后不残留 Hook 子进程、网络请求或未回收的异步任务。

### F15：Hook 状态查看

- 提供只读 `/hooks` 命令，列出已加载 Hook 的名称、事件、动作类型、来源、是否仅执行一次和是否异步。
- 列表顺序稳定，便于排查实际加载结果。
- 没有 Hook 时给出明确空状态；输出不展示敏感请求头、命令中的秘密值或完整配置正文。

### F16：历史与既有能力一致性

- Hook 提醒、拦截、失败、超时和异步执行均不制造悬空工具调用、不合法角色顺序或损坏的持久会话记录。
- Hook 执行完成或失败后，用户仍可继续对话、恢复会话、执行工具和使用既有命令。
- 本章新增能力不改变现有权限系统对普通模型工具调用的判断流程。

## 非功能需求

- **N1：界面不阻塞**——异步 Hook、HTTP 请求和 Shell 执行期间，TUI 保持响应；同步 Hook 也必须受到短而明确的超时约束。
- **N2：时间有界**——所有外部动作均有默认超时，单条配置可覆盖；超时后尽快停止并返回可读结果。
- **N3：顺序确定**——同步 Hook 按项目级在前、用户级在后的稳定顺序执行；异步 Hook 的触发和结果可区分，不干扰同步拦截顺序。
- **N4：权限兼容**——统一匹配能力不能改变已有权限规则的含义，现有配置和测试继续通过。
- **N5：历史合法**——动态提醒不持久化，工具拦截结果与对应调用配对，任何 Hook 结果都不破坏 provider 所需的消息结构。
- **N6：敏感信息安全**——Hook 列表、错误提示、日志和界面不回显 API 密钥、Authorization、密码或敏感环境变量。
- **N7：退出整洁**——程序退出后不残留 Hook 创建的后台任务、子进程或网络请求。
- **N8：配置确定且可降级**——相同配置每次得到相同合并顺序和运行顺序；局部无效配置只影响对应 Hook。
- **N9：代码易读**——实现优先采用普通类、简单函数和清晰分支；不为了 Hook 引入通用事件总线或过度抽象；关键异步和拦截逻辑带中文注释。
- **N10：可验证**——格式、静态检查和自动化测试通过，并使用 tmux 真实验证至少一个自动动作和一个前置拦截场景。

## 不做的事

- 不真正创建或调度子 Agent，只保留动作类型和清晰占位结果。
- 不提供 Hook 的 UI 编辑、删除、启停或热重载；启动时加载，`/hooks` 仅用于查看。
- 不实现条件组嵌套、函数调用、算术计算或完整表达式语言。
- 不允许 Hook 修改模型给出的工具参数，也不允许改写已经成功产生的工具结果。
- 不实现定时任务、文件监听、Server 健康检查或主动轮询触发器。
- 不实现 Hook 自动重试、指数退避或中断后续跑。
- 不建立 Hook 执行历史数据库或独立审计系统。
- 不实现远程 Hook 分发、下载安装或 Hook 市场。
- 不允许 Hook 动作再次递归触发同类 Hook，避免无限循环。
- 不为 Hook 动作重复弹出权限确认；Hook 配置本身视为用户授权。
- 不用 Hook 系统替换现有 Agent 到 TUI 的事件流，也不引入全局通用发布订阅框架。

## 验收标准

- **AC1（F1/F2）配置加载与降级**：项目级与用户级有效 Hook 均能在 `/hooks` 中看到；构造重名 Hook、非法 YAML、未知事件和非法正则时，对应项被跳过并显示可读信息，程序仍能启动。
- **AC2（F3/N4）统一匹配与兼容**：精确、glob、正则和取反匹配分别验证命中与不命中；已有 `Bash(git *)` 权限规则行为不变，原权限测试继续通过。
- **AC3（F4）条件判断**：嵌套字段、`all_of` 和 `any_of` 分别按预期判断；字段缺失时不报错且不触发；混用或嵌套条件在加载期被拒绝。
- **AC4（F5/F6）事件与上下文**：自动化测试分别触发 11 个事件，确认每个事件发生在规定时机，并携带正确的通用字段与专用字段。
- **AC5（F7）Shell 自动动作**：配置写文件后的 Python 格式化命令，Agent 修改文件后命令自动执行，且不出现权限弹窗。
- **AC6（F8）工具前置拦截**：配置拒绝指定路径写入，要求 Agent 修改该路径时，真实文件不变，界面显示 Hook 名称和拒绝原因，模型收到结构化结果并能调整答复。
- **AC7（F8）用户输入拦截**：配置拒绝指定用户输入，提交后该消息不进入历史，界面显示原因且输入仍可编辑；修改为允许内容后可正常提交。
- **AC8（F9/N5）动态提醒与历史**：会话事件产生的 Prompt 动作只影响下一次模型请求，随后清除；提醒不出现在会话 JSONL 中，后续消息角色和工具配对合法。
- **AC9（F10）HTTP 动作与拦截**：使用本地测试 HTTP 服务验证方法、请求头和请求体字段正确；服务返回结构化拒绝时，同步前置操作被阻止。
- **AC10（F11）子 Agent 占位**：触发子 Agent 动作时显示明确的后续章节占位结果，不创建子 Agent，当前会话仍可继续。
- **AC11（F12）执行控制**：`only_once` 在同一会话只执行一次，并在新建或恢复会话后重新计算；异步 Hook 不阻塞主流程；超时 Hook 被停止且程序保持可用。
- **AC12（F13/N1/N2）失败隔离**：分别触发 Shell 非零退出、HTTP 连接失败、HTTP 超时和模板字段缺失，Agent Loop 与 TUI 均不崩溃，之后可继续正常对话。
- **AC13（F14/N7）后台清理**：启动长时间异步 Hook 后退出 Dragon Code，确认没有残留任务、Hook 子进程或未结束请求。
- **AC14（F15/N6）状态查看**：`/hooks` 以稳定顺序展示规定字段；无配置时显示明确空状态；输出不包含敏感请求头或秘密值。
- **AC15（F16/N5）既有能力与历史一致**：经历 Hook 拦截、超时、用户取消和上下文压缩后，继续发起请求不出现 provider 消息结构错误，会话保存和恢复正常。
- **AC16（N10）完整验证**：`uv sync --locked`、`ruff format --check`、`ruff check` 和 `pytest` 全部通过；在 tmux 中真实完成一次写文件后的自动动作和一次危险操作前置拦截，并记录实际可观测结果。
