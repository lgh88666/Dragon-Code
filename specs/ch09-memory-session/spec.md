# ch09：项目记忆与会话持久化 Spec

## 状态

- 阶段：已批准（2026-08-11）
- 教材基线：Vibe Coding ch09 Python 提示词
- 项目适配：教材中的 MewCode 统一替换为 Dragon Code；`.mewcode` 替换为 `.dragon-code`；会话保留期由 30 天调整为 45 天
- 已确认选择：分层增量接入；启动默认创建新会话；通过 `/resume` 手动恢复；每 5 个自然完成轮次或命中明确关键词时更新记忆；记忆更新后台静默执行；JSONL 写入失败时继续对话并显示警告

## 背景

Dragon Code 已经具备多协议对话、工具调用、Agent Loop、权限控制、MCP、系统提示工程和上下文压缩等能力，但这些能力主要服务于当前进程。退出程序后，对话历史无法恢复；每次启动都需要重新说明项目背景、编码规范和用户偏好；Agent 无法在不同会话之间积累纠正经验。ch08 创建的会话目录目前只保存大型工具结果，并不保存完整对话。

ch09 增加三层持久化知识：从多层 `DRAGON.md` 加载人工维护的项目规则；把完整对话追加保存为 JSONL 并支持 `/resume`；把用户偏好、纠正反馈、项目知识和参考资料沉淀为 Markdown 笔记，并在后续请求中自动提供给模型。

本章采用分层增量方案，分别实现项目指令、会话存档和自动记忆，再接入现有系统提示、Conversation 与 Agent Loop，不建立统一的大型存储框架。

## 目标

- **项目规则自动恢复**：启动时加载用户级和项目级 `DRAGON.md`，让模型在第一次请求前了解项目约定。
- **引用安全可控**：项目指令支持引用其他文件，同时限制嵌套深度、防止循环引用和越界读取。
- **会话持续保存**：对话按 JSONL 追加写入磁盘，降低程序异常退出时的历史损失。
- **历史会话可恢复**：每次启动默认创建新会话；用户可通过 `/resume` 选择历史会话继续交流。
- **异常存档可修复**：恢复时跳过损坏记录、处理悬空工具调用，并在历史过长时先执行上下文压缩。
- **长期记忆自动积累**：每完成五轮对话，或用户明确表达“记住”等意图时，在后台更新长期记忆。
- **记忆分类存储**：区分用户偏好、纠正反馈、项目知识和参考资料，并分别保存到用户级或项目级目录。
- **请求前自动注入**：只把受控大小的记忆索引提供给模型，需要详情时再通过文件工具读取原文。
- **运行过程不中断**：项目指令、会话保存或自动记忆中的单项失败不导致 Agent Loop 崩溃。
- **数据生命周期受控**：自动清理超过 45 天的历史会话，不自动删除长期记忆。

## 功能需求

### 第一层：项目指令文件

- **F1 三层指令扫描**：启动时依次加载项目根目录 `DRAGON.md`、项目 `.dragon-code/DRAGON.md`、用户 `~/.dragon-code/DRAGON.md`。高优先级内容排在前面，文件缺失则跳过。
- **F2 引用语法**：独占一行的 `@include <relative_path>` 替换为目标文件内容；路径相对当前文件解析，引用文件还可继续引用。段落中的 `@include` 保持原文。
- **F3 深度限制**：引用最多展开 5 层。超过限制时保留原引用行，并追加可读警告。
- **F4 环路检测**：通过规范化绝对路径识别循环引用；同一文件在当前展开链中不能重复加载，命中时跳过并追加警告。
- **F5 路径边界**：项目级指令只能引用项目根目录内文件；用户级指令只能引用 `~/.dragon-code/` 内文件。越界引用必须拒绝。
- **F6 异常文件处理**：文件不存在时静默跳过，空文件产生空内容；前 512 字节包含空字节的文件视为二进制文件，跳过并追加警告。
- **F7 指令注入**：加载后的指令内容进入系统提示的“自定义指令”模块；没有内容时跳过该模块。
- **F8 启动时冻结**：项目指令在进程启动时加载一次，当前进程内不监听文件变化。

### 第二层：会话存档

#### 会话身份与目录

- **F9 会话 ID**：新会话 ID 使用本地时间和随机后缀组成的 `YYYYMMDD-HHMMSS-xxxx` 格式，并同时用于会话存档和 ch08 工具结果目录。
- **F10 统一目录**：每个会话使用 `.dragon-code/sessions/<session_id>/`；对话存档为 `conversation.jsonl`，大型工具结果位于其 `tool-results/` 子目录。

#### JSONL 格式

- **F11 单行记录**：每条消息写成一行 JSON，支持角色、正文、工具调用、工具结果、Unix 时间戳；第一条消息额外记录模型名。
- **F12 压缩标记**：ch08 完成历史压缩时，先追加一条 compact 标记，再写入压缩后的消息。恢复时只采用最后一个有效标记后的内容。
- **F13 追加时机**：用户消息、助手消息、工具调用、工具结果在形成完整逻辑消息后写入；整体压缩替换时记录 compact 标记和替换后的消息。
- **F14 只追加不重写**：正常对话期间不重写已有 JSONL 内容；异常退出最多影响正在写入的最后一行。

#### 会话写入

- **F15 原子追加**：同一会话的写入必须串行保护，每次追加后刷新并同步到磁盘。写入失败时当前对话继续运行，界面提示“本轮未能保存”。
- **F16 生命周期关闭**：程序退出或切换会话时关闭旧文件句柄，避免文件占用和资源泄漏。

### 第三层：会话恢复

- **F17 `/resume` 命令**：仅在空闲状态允许执行 `/resume`，该命令不发送给模型。
- **F18 会话扫描**：扫描 `.dragon-code/sessions/` 中包含 `conversation.jsonl` 的新格式会话，并按最近修改时间倒序排列。
- **F19 选择界面**：使用方向键选择、文字搜索过滤、Enter 确认和 Esc 取消；恢复期间进入独立的界面状态。
- **F20 列表信息**：每项显示第一条用户消息形成的标题、相对时间、模型名称和 JSONL 文件大小；标题最多展示 50 个字符。
- **F21 恢复与修复**：从最后一个 compact 标记后逐行恢复；坏行跳过；末尾悬空工具调用截断；Token 超过 ch08 阈值时先尝试压缩；中断超过 6 小时时追加时间跨度提醒。
- **F22 切换当前会话**：恢复成功后替换当前 Conversation、会话上下文和写入目标，后续消息继续追加到被恢复会话的原 JSONL。
- **F23 恢复反馈**：恢复期间显示加载状态；成功后显示会话 ID 和恢复的消息数量。
- **F24 保留新会话**：执行 `/resume` 前自动创建的新会话目录不删除，即使它只有少量记录。

#### 会话清理

- **F25 过期清理**：启动时删除时间戳超过 45 天的新格式会话目录，包括其 JSONL 和工具结果。
- **F26 后台执行**：会话清理异步进行，不阻塞启动；单个目录清理失败不影响其他目录。

### 第四层：自动记忆

#### 记忆存储

- **F27 四种类型**：支持用户偏好、纠正反馈、项目知识和参考资料四类记忆。
- **F28 Markdown 格式**：每条记忆是一份 Markdown，frontmatter 至少包含类型、标题、创建时间和更新时间。
- **F29 两级目录**：项目知识和参考资料通常保存到项目 `.dragon-code/memory/`；用户偏好和纠正反馈通常保存到 `~/.dragon-code/memory/`，最终层级由模型判断。
- **F30 记忆索引**：两级目录分别维护 `MEMORY.md`，每行记录类别、标题和一句话描述；每份索引最多 200 行、25KB。
- **F31 文件命名**：文件名为 `<type>_<short_slug>.md`，slug 使用小写字母和下划线。

#### 记忆注入

- **F32 索引重新加载**：启动时加载项目级和用户级索引；每次记忆更新完成后重新加载，使当前会话后续请求可以使用新记忆。项目级排在用户级之前。
- **F33 只注入索引**：系统提示只放入索引文本，不放入全部笔记正文；模型需要详情时通过 Read 工具读取对应文件。
- **F34 注入大小限制**：两级索引合计超过 25KB 时截断，并追加 `(index truncated)` 标记。

#### 记忆更新

- **F35 触发条件**：Agent Loop 自然完成且输出最终答复后，每完成 5 个自然结束轮次，或用户消息包含“记住、记忆、别忘、remember、memo”等明确意图时触发记忆更新。取消、流错误和迭代上限停止时不触发。
- **F36 异步更新**：记忆更新在后台任务中执行，不阻塞下一次用户输入。
- **F37 更新输入**：向当前活动模型提供本轮从用户输入到最终答复的消息快照，以及项目级、用户级完整索引。
- **F38 禁止工具**：记忆更新请求不提供任何工具定义，模型只能返回记忆决策。
- **F39 结构化决策**：模型返回操作数组，操作仅允许 create、update、delete；每项明确层级、类别、标题、文件名或内容。空数组表示无需更新。
- **F40 执行操作**：create 创建笔记并增加索引；update 更新笔记与索引；delete 删除笔记并移除索引。所有路径必须限制在对应的 memory 目录内。
- **F41 模型去重**：更新请求携带完整索引，由模型判断新增、合并、更新或跳过相似记忆。
- **F42 静默失败**：模型错误、JSON 解析失败或文件写入失败时只记录内部日志，不展示到对话区、不重试、不影响主会话。

### 集成与生命周期

- **F43 提示模块接入**：系统提示装配同时接收项目指令和记忆索引，分别放入“自定义指令”和“长期记忆”模块；空内容不产生空模块。
- **F44 Conversation 持久化挂钩**：消息追加和整体历史替换都能通知会话写入器；未启用持久化时，Conversation 行为与 ch08 保持一致。
- **F45 启动顺序**：启动时依次加载项目指令、初始化记忆并加载索引、启动会话清理，然后再组装 TUI 与系统提示。
- **F46 恢复互斥**：Agent Loop 运行时执行 `/resume`，只提示等待当前任务完成；恢复会话期间不能发起新的 Agent Loop。
- **F47 与压缩并发**：后台记忆更新只读取 Conversation 快照、只修改 memory 目录，不修改当前 Conversation，因此可与 `/compact` 同时执行；两者不能相互破坏状态。

## 非功能需求

- **N1 性能**：项目指令及 `@include` 展开应在 200ms 内完成；单条 JSONL 序列化、追加和刷盘目标不超过 10ms；扫描并展示 50 个历史会话目标不超过 500ms。
- **N2 并发安全**：同一会话的 JSONL 追加必须串行保护；记忆目录写入需要加锁，避免两个后台记忆更新同时修改笔记或索引。
- **N3 向后兼容**：不存在 `DRAGON.md`、memory 目录或历史会话时，Dragon Code 仍可正常启动；ch08 旧格式会话目录不进入 `/resume` 列表，也不被自动清理。
- **N4 可测试性**：指令加载、引用展开、JSONL 解析、历史修复、会话列表和记忆索引等核心逻辑，必须能够在不调用真实模型的情况下测试；记忆更新使用可替换的假 LLMClient。
- **N5 错误隔离**：指令加载、JSONL 写入、历史恢复、自动压缩、记忆更新和过期清理中的单项失败不能导致程序崩溃，也不能拖垮其他会话功能。
- **N6 本地数据安全**：自动生成的会话存档和项目级记忆默认加入 `.gitignore`；API Key、Authorization、敏感环境变量不得写入 JSONL、记忆、项目指令警告或日志。
- **N7 现有能力不退化**：ch02–ch08 的对话、流式输出、工具调用、MCP、权限审批、Plan Mode、提示缓存、上下文压缩和用户取消行为保持不变。
- **N8 界面不阻塞**：会话清理、列表扫描和自动记忆更新不得阻塞 Textual 事件循环；运行期间输入、滚动、计时和状态展示保持响应。
- **N9 退出整洁**：退出或切换会话时关闭 JSONL 文件句柄；后台记忆任务和清理任务应正常完成或安全取消，不留下挂起任务。
- **N10 代码规范**：实现保持简单直观，关键异步、恢复和安全逻辑使用中文注释；通过项目规定的 Ruff、pytest 和 tmux 端到端验收。

## 不做的事

- **不做向量数据库或 RAG**：记忆索引直接进入上下文，不实现向量化、Embedding 或语义检索。
- **不做团队记忆同步**：项目记忆和用户记忆只保存在本机，不同步给其他成员或远程服务。
- **不做自动恢复最近会话**：启动始终创建新会话，只能由用户输入 `/resume` 手动恢复。
- **不做会话合并**：每个会话独立保存，不支持把多个 JSONL 合并为一个会话。
- **不做完整会话管理器**：本章不增加会话重命名、导出、收藏和手动删除等功能。
- **不做记忆质量评估**：记忆提取 Prompt 使用固定方案，不进行用户评分、A/B 测试或自动效果优化。
- **不做指令热更新**：`DRAGON.md` 只在启动时加载一次，运行中修改不会立即生效。
- **不做笔记全文搜索**：模型通过 `MEMORY.md` 索引了解已有记忆，需要详情时使用 Read 工具读取文件。
- **不清理旧格式会话**：无法从 ID 中安全解析时间的 ch08 历史目录不展示、不自动删除。
- **不做云端备份或加密存储**：会话和记忆使用本地文件保存，本章不增加云同步和文件加密。
- **不做通用 Slash Command 框架**：`/resume` 继续沿用当前 TUI 的直接命令分发方式，通用命令注册体系留给 ch10。
- **不持久化流式碎片**：不会把每个文本增量逐条写入磁盘，只保存已经形成的完整逻辑消息。

## 验收标准

### 项目指令

- **AC1 三层加载**：三个位置分别放置 `DRAGON.md`，启动后系统提示的自定义指令模块包含三份内容，项目根内容排在最前。
- **AC2 缺失文件**：只提供项目根 `DRAGON.md`，其余文件不存在，Dragon Code 仍正常启动且只注入已有内容。
- **AC3 引用展开**：指令中写入独占一行的 `@include rules/style.md`，最终注入内容包含目标文件正文，原引用行被替换。
- **AC4 深度限制**：构造 6 层引用，第 6 层不展开，并出现“超过最大嵌套深度”的警告。
- **AC5 环路检测**：A 引用 B、B 再引用 A，不发生无限递归，并出现环路警告。
- **AC6 路径逃逸**：项目指令尝试引用项目外文件时拒绝读取，并出现范围警告。

### 会话存档

- **AC7 会话 ID**：启动后会话 ID 符合 `YYYYMMDD-HHMMSS-xxxx`，对应目录同时容纳 JSONL 和 ch08 工具结果。
- **AC8 JSONL 写入**：完成一轮对话后，`conversation.jsonl` 至少包含用户和助手记录；每行都是合法 JSON，并包含角色、正文和时间戳，首条记录包含模型名。
- **AC9 压缩标记**：触发 `/compact` 后，JSONL 出现 compact 标记，其后追加压缩后的消息。
- **AC10 崩溃安全**：模拟最后一行写入不完整，重新恢复时此前完整行均可解析，损坏的最后一行被跳过。

### 会话恢复

- **AC11 `/resume` 路由**：空闲态输入 `/resume` 不请求 LLM，而是打开会话列表；按 Esc 返回空闲状态。
- **AC12 列表展示**：存在三个有效会话时，列表显示三项，每项具有标题、相对时间、模型和文件大小。
- **AC13 搜索过滤**：输入标题关键词后，只显示匹配的历史会话。
- **AC14 坏行跳过**：在 JSONL 中插入非法内容，恢复后其余合法消息仍被加载。
- **AC15 悬空调用修复**：JSONL 末尾只有 Assistant ToolCall 而没有对应 ToolResult，恢复时从该 Assistant 消息之前截断。
- **AC16 超限压缩**：恢复一个超过 ch08 自动压缩阈值的会话，进入空闲状态前自动尝试一次压缩。
- **AC17 时间提醒**：恢复最后消息距当前超过 6 小时的会话，Conversation 末尾出现时间跨度提醒。
- **AC18 原会话续写**：恢复后发送新消息，新记录追加到被恢复会话原有的 JSONL 中。

### 会话清理

- **AC19 45 天清理**：创建一个 46 天前的新格式会话和一个 44 天前的会话，启动清理后前者被删除，后者保留。
- **AC20 旧格式保护**：旧格式 session ID 目录不进入 `/resume` 列表，也不被自动删除。

### 自动记忆

- **AC21 笔记创建**：用户明确说“记住我偏好简洁回复”，自然完成后对应 memory 目录出现合法 Markdown；frontmatter 包含类型、标题和创建时间，文件名符合规定。
- **AC22 索引更新**：创建、更新或删除笔记后，对应 `MEMORY.md` 的摘要行同步变化。
- **AC23 记忆注入**：索引存在时启动新会话，系统提示的长期记忆模块包含项目级和用户级索引；记忆更新完成后，当前会话后续请求能使用更新后的索引。
- **AC24 异步不阻塞**：记忆更新仍在执行时提交下一条消息，新消息可以立即进入正常处理流程。
- **AC25 失败静默**：模拟记忆更新请求失败，主会话继续运行，对话区不出现记忆错误，内部日志记录失败原因。
- **AC26 索引限制**：构造超过 25KB 的合并索引，注入内容被限制到 25KB，并带有 `(index truncated)` 标记。

### 集成

- **AC27 系统提示接入**：分别传入项目指令和记忆索引时，对应模块按正确位置出现；传入空内容时模块被跳过，原有七个固定模块不受影响。
- **AC28 Conversation 持久化通知**：用户消息、助手消息、工具结果和整体历史替换均能触发对应的存档动作；未设置持久化时行为与 ch08 一致。
- **AC29 状态互斥**：Agent Loop 运行期间输入 `/resume` 只显示等待提示；会话恢复期间无法启动新的 Agent Loop。
- **AC30 压缩并发**：后台记忆更新期间执行 `/compact`，两者均可正确结束；Conversation、JSONL 和 `MEMORY.md` 没有损坏或交叉覆盖。
- **AC31 触发条件**：连续完成四轮普通对话不自动更新记忆，第五轮触发；任意一轮出现“记住”等关键词时立即触发；取消或错误结束的轮次不触发。
- **AC32 保存失败降级**：模拟 JSONL 写入失败，界面显示“本轮未能保存”，当前回复仍能完成，用户可以继续下一轮对话。

### 端到端场景

在 tmux 中使用真实 Dragon Code 完成：

1. 启动后确认 `DRAGON.md` 和记忆索引已进入模型上下文。
2. 进行包含内置工具调用的真实对话，检查 JSONL 中用户、助手、工具调用和结果完整配对。
3. 退出并重新启动，使用 `/resume` 选择该会话。
4. 追问前文信息，模型能引用已恢复的对话。
5. 明确要求“记住一个偏好”，等待后台更新完成。
6. 启动新会话，确认模型能遵守保存的偏好。
7. 使用 `/exit` 退出，确认文件句柄、后台任务和终端状态均正确清理。
