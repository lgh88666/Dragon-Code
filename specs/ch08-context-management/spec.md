# ch08：上下文管理 Spec

## 状态

- 阶段：已批准（2026-08-08）。
- 教材基线：Vibe Coding ch08 Python 提示词。
- 项目适配：沿用 Dragon Code 当前的长生命周期 Agent、现有 TUI 命令分发和协议无关消息模型。
- 本文档已完成逐段确认；后续设计与实现不得超出本 Spec。

## 背景

Dragon Code 的每次模型请求都会携带系统提示、可用工具定义和当前进程中的完整对话历史。随着 Agent Loop 持续读取文件、执行命令和调用 MCP，工具结果会反复进入后续请求，请求体会不断增大，最终可能超过模型的上下文窗口。

当前 Read、Bash、Grep 和 MCP 等工具还会在各自执行阶段提前截断输出。这样虽然限制了单次返回大小，但被截掉的完整结果无法恢复，也不能实现“对话只留预览、需要时按路径重读”的上下文管理。

本章采用两层策略：

1. **轻量预防**：所有工具结果统一接受大小检查；超限结果保存到磁盘，对话中只保留稳定预览和重读路径。
2. **重量兜底**：整体请求接近模型上下文窗口时，使用专门的摘要模型生成结构化摘要，以摘要、边界提示和近期原文替换旧历史。

## 目标

- **长任务可持续**：显著降低长时间 Agent Loop 因历史膨胀而撞上上下文窗口的概率。
- **完整结果可恢复**：被替换的工具结果仍完整保存在项目会话目录中，模型可显式重读。
- **用户意图尽量保真**：近期用户消息保留原文；较早用户消息在摘要中优先逐条保留原始表达。
- **缓存前缀稳定**：同一工具调用一旦决定替换或保留，本会话内不反复改变，避免相同历史在不同请求中产生不同文本。
- **跨 Provider 可配置**：上下文窗口由 Provider 配置决定，未配置时按协议使用默认值。
- **失败不破坏历史**：落盘或摘要失败时，原 Conversation 保持有效，程序不崩溃。
- **用户可控**：用户可以通过 `/compact` 主动触发摘要，并看到压缩前后的估算 Token。

## 用户可观察行为

### 超大工具结果

当工具返回超大内容时，TUI 和后续对话不会展示或携带完整内容，而会看到一段稳定预览。预览必须包含：

1. 原始 UTF-8 字节数。
2. 内容头部预览。
3. 完整结果保存路径。
4. 使用 Read 工具重新读取该路径的提示。

为避免完整结果再次超过阈值后形成“读取—再次落盘”的循环，Read 支持可选的
`offset`（起始行，1-based）和 `limit`（最多行数）。不传参数时仍返回完整文件；
预览同时给出原始行数和分段读取示例，模型可按段恢复任意行区间。

完整内容保存在：

```text
.dragon-code/sessions/<session_id>/tool-results/<result_file>
```

进程退出后不自动删除该目录。

### 自动压缩

当估算 Token 达到自动阈值时，在下一次普通模型请求发出前：

1. TUI 显示“正在压缩上下文”。
2. Dragon Code 使用摘要模型生成结构化摘要，且摘要请求不提供任何工具。
3. 成功后显示压缩前后的估算 Token，并继续原任务。
4. 失败时保留原历史、显示警告，并继续本轮主模型请求。

### 手动压缩

用户在空闲状态输入 `/compact` 时：

- 不把命令写入 Conversation。
- 不发起普通对话请求。
- 不受自动阈值和熔断状态限制，无条件尝试一次摘要。
- 成功后显示压缩前后的估算 Token。
- 失败后显示原因，原历史保持不变。

## 配置需求

每个 Provider 支持两个可选字段：

- `context_window`：当前模型上下文窗口，单位为 Token。
- `summary_model`：用于生成上下文摘要的模型名。

默认行为：

- Anthropic 未配置 `context_window` 时使用 200000。
- OpenAI 及兼容端点未配置时使用 128000。
- 未配置 `summary_model` 时复用主对话模型。
- 配置 `summary_model: deepseek-v4-flash` 时，摘要模型复用当前 Provider 的协议、API Key 和 `base_url`，只替换模型名。
- 旧配置文件不增加这两个字段也必须正常加载。

配置示例文件需要展示这两个字段，但不得写入真实密钥。

## 功能需求

### F1：统一工具结果入口

- Read、Write、Edit、Bash、Glob、Grep 和 MCP 等所有工具结果统一经过上下文管理。
- 工具自身不再因为原有 100000 字符或固定结果条数上限而永久丢弃本次完整文本结果。
- 上下文管理必须发生在结果写入 Conversation 和显示给 TUI 之前。
- 普通小结果保持现有语义，不改变成功、失败、元数据和调用 ID。
- Read 新增可选行分页参数，默认行为保持完整读取；落盘预览必须提示按段重读，避免大结果重读循环。

### F2：单条工具结果落盘

- 单个工具结果的 `content` 超过 50000 个 UTF-8 字节时，保存完整内容并用预览替换。
- 大小按 `len(content.encode("utf-8"))` 的语义计算，不按 Python 字符数计算。
- 预览头部同时满足“不超过前 20 行”和“不超过 2048 个 UTF-8 字节”，取两种限制中更短的结果。
- 字节裁剪不得产生无效 UTF-8 文本。

### F3：单轮聚合控制

- 同一条工具结果消息中的多个结果，在完成单条阈值处理后，对尚未替换结果的内容合计字节数进行检查。
- 合计超过 200000 字节时，按结果大小从大到小继续落盘，直到剩余合计不超过 200000 字节。
- 只替换让聚合重新达标所需的最少数量。
- 相同大小时保持模型原始调用顺序，保证行为稳定。

### F4：决策冻结与幂等

- 每个工具调用 ID 在本会话内只形成一次最终“保留或替换”决定。
- 被替换结果后续请求始终使用逐字节相同的预览字符串。
- 已落盘结果不重复写入，重复处理不能改变文件内容或修改时间。
- 落盘失败时不得记录为已完成决定；本轮保留原文，后续请求可重新尝试。
- 落盘、生成预览和记录决定必须作为一个一致性动作；不能出现对话指向不存在文件的状态。

### F5：会话目录

- 每次进程会话生成一个唯一且适合 Windows 路径的会话 ID。
- 工具结果文件位于项目内 `.dragon-code/sessions/<session_id>/tool-results/`。
- 结果文件名必须能稳定对应原工具调用 ID，同时避免非法路径字符、目录穿越和名称冲突。
- 目录按需创建；进程退出后保留，不自动清理历史目录。

### F6：请求 Token 估算

- 在不引入精确 tokenizer 的情况下，估算“当前完整请求如果发出会占用多少 Token”。
- 估算覆盖系统提示、环境块、消息历史、工具定义和本轮临时提醒。
- 上一次普通主对话请求返回的真实 usage 作为锚点；之后新增内容按字符数除以 3.5 做增量估算。
- 摘要请求自己的 usage 不得覆盖主对话锚点。
- 每次普通模型请求结束后，用该次最新 usage 替换锚点，不做跨请求累加。

### F7：自动摘要触发

- 自动阈值为 `context_window - 20000 - 13000`。
- 20000 Token 为摘要输出预留，13000 Token 为自动路径估算误差和单轮波动安全余量。
- 每次普通模型 API 请求发出前，先执行工具结果预防处理，再估算整体请求，最后决定是否自动摘要。
- 未达到阈值时不得发起摘要请求。

### F8：摘要请求

- 摘要使用 `summary_model`，复用当前 Provider 的协议、API Key 和 `base_url`。
- 摘要请求不携带任何工具定义，Prompt 首尾都必须明确禁止调用工具。
- Prompt 要求模型先在 `<analysis>` 中生成临时分析草稿，再在 `<summary>` 中生成正式摘要。
- Dragon Code 丢弃分析草稿，只保存可解析的 `<summary>` 内容。
- 缺少合法 `<summary>`、返回工具调用、空摘要或请求异常都视为摘要失败。

正式摘要固定包含九部分：

1. 主要请求和意图。
2. 关键技术概念。
3. 文件和代码段。
4. 错误与修复。
5. 问题解决过程。
6. 用户消息原文。
7. 待办任务。
8. 当前工作和停止位置。
9. 可能的下一步。

### F9：近期原文

- 摘要成功后，从原历史尾部向前选取近期原文。
- 必须同时满足累计估算不少于 10000 Token、消息不少于 5 条；达到两个下界后才停止向前扩展。
- 不允许把 Assistant 工具调用与对应 Tool Result 拆开。
- 如果边界落在一组工具调用和结果之间，必须把边界向前扩展到该组 Assistant 消息之前。
- 近期原文保持原始消息内容和顺序。

### F10：压缩后历史

摘要成功后，Conversation 原子替换为：

```text
结构化摘要
  ↓
固定边界提示
  ↓
近期原文
```

边界提示必须明确告诉模型：需要文件原文、错误原文或精确代码时，使用 Read 重新读取，不得根据摘要猜测。

本章不在恢复段中重复注入最近文件快照或工具定义；下一次普通请求仍通过现有 `LLMRequest.tools` 获得真实工具集合。

### F11：自动摘要熔断

- 自动摘要连续失败 3 次后，本进程会话内停止继续自动触发。
- 第 1 或第 2 次失败后如果后续自动摘要成功，连续失败计数清零。
- 熔断只影响自动路径；手动 `/compact` 始终可以尝试。
- 手动摘要成功或失败不改变自动路径的连续失败计数。
- 进入熔断后 TUI 显示明确提示，引导用户使用 `/compact`。
- 新进程会话重新开始时熔断状态重置。

### F12：失败降级

- 自动摘要失败时保留原 Conversation，显示警告，然后继续本轮主模型请求。
- 手动摘要失败时保留原 Conversation，并显示“压缩失败”。
- 自动失败必须计入熔断；手动失败不计入。
- 工具结果落盘失败只影响该条结果，不得中断 Agent Loop，也不计入摘要熔断。

### F13：手动 `/compact`

- `/compact` 只在当前 Agent 任务空闲时执行；运行中保持现有输入禁用行为，不引入并发压缩。
- 命令直接接入当前 TUI 命令判断，不在 ch08 提前建立通用命令注册表。
- 手动压缩无视自动触发阈值和熔断状态。
- 手动路径使用 3000 Token 安全余量评估摘要请求风险；如果摘要请求预计无法放入当前窗口，必须失败并保留原历史，不能先破坏 Conversation。
- `/help` 需要展示 `/compact` 及其作用。

### F14：压缩事件与界面

- 自动压缩开始、成功、失败和进入熔断都必须形成 TUI 可消费的状态事件。
- 手动压缩成功时显示压缩前后估算 Token。
- 压缩过程不得把摘要草稿、摘要 Prompt 或内部状态写入普通聊天历史。
- TUI 在压缩期间保持可取消和可安全退出，不显示为无响应。

## 固定常量

本章使用以下代码内常量，不增加独立配置项：

| 含义 | 值 |
|---|---:|
| 单条工具结果阈值 | 50000 UTF-8 字节 |
| 单轮工具结果聚合阈值 | 200000 UTF-8 字节 |
| 预览最大行数 | 20 |
| 预览最大字节数 | 2048 |
| 字符 Token 估算比 | 3.5 字符/Token |
| 摘要输出预留 | 20000 Token |
| 自动安全余量 | 13000 Token |
| 手动安全余量 | 3000 Token |
| 近期原文 Token 下界 | 10000 Token |
| 近期原文消息下界 | 5 条 |
| 自动摘要熔断阈值 | 连续失败 3 次 |

## 非功能需求

- **响应性**：文件落盘不得长时间阻塞 Textual/asyncio 事件循环。
- **一致性**：Conversation 只在完整摘要和新历史都构造成功后一次性替换。
- **安全性**：不得在日志、预览、摘要错误或配置示例中泄露 API Key、Authorization Header 或本机敏感环境。
- **路径安全**：结果文件只能写入当前项目的会话目录，工具调用 ID 不能造成目录穿越。
- **可测试性**：大小判断、预览、聚合选择、决策冻结、Token 估算、近期原文边界、摘要解析和熔断均可使用 fake client 离线测试。
- **向后兼容**：未触发压缩时，现有对话、工具、权限、MCP、Plan Mode、提示缓存和取消行为保持不变。
- **缓存稳定**：相同历史在没有新增消息时重复组装，工具预览和压缩边界文本必须逐字节稳定。
- **可观察性**：压缩事件至少暴露原因、压缩前估算、压缩后估算、落盘结果数量和错误状态。

## 明确不做

- 不实现精确 tokenizer。
- 不实现摘要策略的机器学习优化、评分回流或 A/B 测试。
- 不实现 `prompt_too_long` 紧急压缩和主请求自动重试。
- 不实现摘要请求自身过长后的消息组丢弃重试。
- 不恢复最近读取文件快照。
- 不在恢复消息中重复渲染工具列表。
- 不实现跨进程 Conversation 持久化和 `/resume`。
- 不自动清理 `.dragon-code/sessions/` 历史目录。
- 不提前实现 ch10 的通用 Slash Command 注册框架。
- 不支持同一进程多个独立 Agent 会话并行共享上下文状态。

## 可观测验收标准

### AC1：单条落盘

构造一个超过 50000 UTF-8 字节的工具结果：

- Conversation 中只有稳定预览。
- 预览含原始字节数、头部、路径和重读提示。
- 头部不超过 20 行和 2048 字节。
- 会话目录中的文件与原始完整内容逐字节相同。
- 使用预览中的路径和 Read `offset`/`limit` 能读取尾部区间，而不会再次产生超过阈值的完整结果。

### AC2：聚合落盘

同轮返回五个各 45000 字节的结果时，只落盘让剩余合计回到 200000 字节以内所需的最少结果，并保持确定性选择。

### AC3：幂等与失败恢复

- 同一调用重复处理不会重写文件或改变预览。
- 模拟第一次磁盘写入失败时保留原文且不冻结决定；下一轮恢复磁盘后能够重新落盘。

### AC4：配置兼容

- Anthropic、OpenAI 默认上下文窗口正确。
- 显式 `context_window` 覆盖默认值。
- `summary_model` 使用同一端点创建摘要请求。
- 旧配置不含新增字段仍正常启动。

### AC5：自动阈值

- 估算低于 `context_window - 33000` 时不摘要。
- 达到阈值时在主模型请求前摘要。
- 摘要请求的工具定义为空。

### AC6：摘要和近期原文

- 只保存 `<summary>`，分析草稿被丢弃。
- 摘要包含九个固定部分。
- 近期原文同时达到 10000 Token 和 5 条消息下界。
- 工具调用与结果没有被截断边界拆开。
- 新历史包含固定边界提示。

### AC7：自动失败与熔断

- 前两次自动摘要失败后保留历史并继续主请求。
- 第三次连续失败进入熔断。
- 熔断后不再自动发起摘要，但 `/compact` 仍能调用摘要模型。
- 在熔断前出现一次自动摘要成功会清零失败计数。

### AC8：手动命令

- 低 Token 会话输入 `/compact` 仍执行摘要。
- 命令不进入 Conversation，也不触发普通对话请求。
- 成功显示压缩前后 Token，失败保持原历史。
- `/help` 能看到 `/compact`。

### AC9：真实端到端场景

在 tmux 中使用真实 DeepSeek 配置：

1. 主对话模型正常执行会产生大结果的工具调用。
2. 大结果被保存到 `.dragon-code/sessions/<session_id>/tool-results/`，模型收到预览并能通过 Read 重读保存文件。
3. 使用较小的测试 `context_window` 触发自动摘要，摘要请求使用 `deepseek-v4-flash` 且无工具调用。
4. TUI 显示压缩开始及前后 Token，压缩后继续完成当前任务。
5. 手动 `/compact` 在低 Token 会话也可执行。
6. `/exit` 后落盘目录仍保留，终端与后台任务正确清理。

## 待批准选择汇总

- 采用教材核心两层压缩，而非一次实现全部紧急恢复路径。
- 所有工具统一处理完整结果。
- 自动摘要熔断纳入本章。
- Provider 支持 `context_window`，默认 Anthropic 200K、OpenAI 128K。
- 摘要使用同端点的 `deepseek-v4-flash`；未配置时回退主模型。
- 自动摘要失败后保留历史并继续主请求。
- `/compact` 沿用现有 TUI 命令判断，命令注册表留到 ch10。
- 会话工具结果目录退出后保留，不自动清理。
