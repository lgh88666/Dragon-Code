# 系统提示工程化 Spec

## 背景

ch04 已让 Dragon Code 具备完整的 Agent Loop，可以自主多轮调用工具直到任务完成。但当前系统提示仍是一段整体文本，身份、工具规则、环境信息、输出风格和模式约束混在一起，缺少清晰结构和优先级。

每轮请求还会重复发送稳定不变的系统指令和工具定义，无法有效利用模型服务的 Prompt Cache。工作目录、平台、日期和 Git 状态等环境信息没有形成独立动态内容；Plan Mode 提醒则直接追加到系统提示尾部，无法控制注入频率。

ch05 将系统提示改造成模块化装配管线，分离稳定内容与动态内容，并通过补充消息机制注入运行时约束。稳定系统模块和工具定义尽力使用模型服务缓存，环境信息、对话历史和补充消息保持动态且不进入缓存。

教材不同页面存在术语差异：Python 源码使用 LLM Client 表示模型协议客户端，Vibe Coding 模板部分位置使用 Provider 泛指同一协议适配层。Dragon Code 内部统一使用 LLM Client；`ProviderConfig` 和 YAML 的 `providers` 继续表示外部模型服务配置。

## 目标

- 把全局指令拆成职责明确、按优先级稳定装配的模块。
- 区分稳定内容和动态内容，让稳定系统模块与工具定义进入可缓存通道。
- 构造独立环境信息块，使模型感知当前运行环境，但不污染稳定缓存。
- 在系统提示和工具描述中双重强化关键工具约定。
- 通过带标签的补充消息动态注入模式约束，不污染持久历史。
- 按 Agent Loop 轮次控制 Plan Mode 提醒的详略和重复频率。
- 解析模型服务返回的缓存写入量和缓存读取量，验证缓存策略实际生效。
- 保持 Anthropic 与 OpenAI 两种协议的上层行为一致，不破坏 ch04 已有能力。

## 功能需求

### F1：模块化系统提示拼装

把全局指令按职责拆成独立模块，每个模块具有名称、优先级和内容。固定模块按照以下顺序装配：

1. 身份
2. 系统约束
3. 任务模式
4. 动作执行
5. 工具使用
6. 语气风格
7. 文本输出

固定模块之后预留三个可选位置：自定义指令、已激活 Skill、长期记忆。本章不接入这三类内容的真实来源。空模块自动跳过，不产生多余标题或空行。新增一类指令时，只需将新模块放到对应优先级，不修改装配主流程。

### F2：环境信息构造与呈现

收集当前工作目录、操作系统和平台、当前日期、Git 分支和工作区状态、Dragon Code 版本、当前模型等运行环境信息，并构造成供模型理解的环境文本。

Dragon Code 内部始终把环境信息作为系统提示的独立第二段保存：稳定系统模块位于第一段并可缓存，环境信息位于第二段且不缓存。Anthropic 将两段映射为两个 system 内容块；OpenAI 为兼容不同端点，可以在请求序列化阶段把两段放入同一条 system 消息，但稳定段必须完整位于环境段之前。环境信息不得混入稳定段的数据来源或改变稳定前缀。

### F3：稳定内容走可缓存通道

稳定系统模块和工具定义进入可缓存通道；环境信息、补充消息和对话历史进入不缓存通道。

可缓存内容在配置、代码及启用模块不变时必须跨轮逐字节一致，不得包含日期、目录状态、迭代次数等动态信息。

Anthropic 请求对稳定系统模块和工具定义设置显式缓存断点，使稳定前缀能够复用；环境块与历史位于不缓存部分。OpenAI 请求把稳定内容保持在请求前缀，利用端点可能提供的自动前缀缓存，不发送 Anthropic 专属字段，也不强制兼容端点必须支持缓存。

### F4：缓存命中解析

从模型服务返回的用量数据中解析输入 Token、输出 Token、缓存写入 Token 和缓存读取 Token，并通过统一用量事件向 Agent 暴露，供测试、烟测或调试输出验证。

Anthropic 解析缓存创建和缓存读取字段；OpenAI 解析端点提供的缓存命中字段。协议或兼容端点未返回缓存字段时，对应缓存用量为零，不影响正常对话。

### F5：关键约定双重强化

以下关键规则同时出现在稳定系统提示和相关工具描述中：

- 优先使用 Read、Edit、Glob、Grep 等专用工具。
- 不使用 Shell 命令拼凑专用工具已经能完成的操作。
- 修改已有文件前必须先读取相关内容。
- 精确修改优先使用 Edit。
- 只有需要真实执行系统命令时才使用 Bash。
- 工具没有明确返回成功时，不得声称操作已经完成。

工具参数的字段描述也应清楚说明用途和重要限制，帮助模型生成正确参数。

### F6：补充消息注入机制

提供一种使用 `<system-reminder>` 标签包裹的补充消息。构造请求时，将补充指令动态注入消息通道，使模型将其理解为系统补充上下文，而不是需要直接回答的用户问题。

补充消息每轮动态构造，不与用户真实问题拼接，不写入持久对话历史，也不在 TUI 中显示。

### F7：规划模式按轮次注入

Plan Mode 提醒通过 F6 的补充消息承载，不再追加到稳定系统提示尾部。

- Agent Loop 第 1、6、11……轮注入完整 Plan Mode 提醒。
- 其他轮次注入精简提醒。
- `/plan` 进入规划模式，模式跨轮保持。
- `/do` 退出规划模式并触发按照上文计划执行。
- Plan Mode 仍只开放 Read、Glob、Grep，由工具注册中心提供实际边界。

### F8：跨协议一致

Anthropic 与 OpenAI，包括兼容 `base_url`，使用相同的固定模块内容和顺序、环境信息、补充消息内容、注入时机和 Plan Mode 提醒节奏。

协议差异由对应 LLM Client 内部处理：Anthropic 使用显式缓存断点，OpenAI 保持稳定请求前缀；两者分别解析自己能够提供的缓存字段，上层 Agent 不感知协议字段差异。

## 非功能需求

- N1：缓存确定性——可缓存块中的模块顺序和工具顺序固定，跨轮逐字节稳定，不混入任何随轮次或时间变化的内容。
- N2：不破坏 ch04 行为——Agent Loop、多轮流式收集、保序分批并发、用户取消、历史一致、用量与迭代进度展示等能力不退化。
- N3：历史合法性——每轮动态补充消息只加入临时请求副本；注入后角色顺序合法，不插入工具调用与对应结果之间，不破坏工具配对，不导致协议返回消息结构相关的 400。补充消息不进入持久历史，任务完成、取消或失败后仍可继续对话。
- N4：环境采集不阻塞、可降级——环境采集快速且有界，可能执行的 Git 检查具有短超时；任一信息无法获取时省略或降级，不中断会话。
- N5：密钥与敏感信息不泄漏——对话区、环境块、调试输出和错误信息不出现 API Key、鉴权头或敏感环境变量；Git 摘要不读取文件内容。
- N6：缓存字段解析健壮——模型服务或兼容端点未返回缓存字段时按零处理，不抛未捕获异常，不中断当前任务或会话。
- N7：代码规范——代码通过格式和 lint 检查，import 分组与项目风格一致；可选类型检查通过。
- N8：可扩展性——新增系统提示模块或补充提醒类型时改动保持局部，不修改装配主流程，不改变 LLM Client 对外接口的语义。

## 不做的事

- 不加载 `CLAUDE.md`、`AGENTS.md` 等项目级指令文件；自定义指令只是预留空槽。
- 不实现自动记忆或长期记忆写入与召回。
- 不接入真实 MCP、Skill 或外部资源；只保留可选模块位置。
- 不建立自动化 Prompt 评测框架，只做缓存字段验证和典型场景人工对比。
- 不对对话历史设置增量缓存断点，只缓存稳定系统模块和工具定义。
- 不配置缓存 TTL 和缓存断点数量，使用协议默认值与内置断点位置。
- 不在 TUI 状态栏展示缓存命中量，只通过统一用量对象和烟测、测试或调试输出验证。
- 不实现提示词运行时热加载或外部模板文件，模块内容内置于代码。
- 不新增多模态和流式工具结果，沿用 ch04 行为。

## 验收标准

- AC1：模块化装配——稳定系统提示由七个固定模块按优先级拼接，模块间只有一个空行；新增测试模块时只需挂载，不修改装配主流程。（F1）
- AC2：可选空槽——自定义指令、已激活 Skill、长期记忆为空时自动跳过且不产生多余空行；提供测试内容时出现在固定模块之后。（F1）
- AC3：环境信息呈现——环境段包含工作目录、平台、当前日期、Git 状态、应用版本和当前模型，并在内部数据结构中与稳定系统模块分离；Anthropic 映射为两个 system 内容块，OpenAI 即使合并为一条 system 消息也保持稳定段完整位于环境段之前。（F2）
- AC4：Anthropic 缓存命中——同一会话连续发送具有相同稳定前缀的请求，首轮观察到缓存写入 Token，后续轮观察到缓存读取 Token；只改变环境信息或历史时稳定前缀仍命中。（F3、N1）
- AC5：缓存确定性——相同固定模块和工具集连续构造两次，稳定系统模块与工具定义逐字节一致；改变日期、目录或 Git 状态不改变稳定块。（F3、N1）
- AC6：缓存字段解析——统一用量对象暴露缓存写入量和读取量；Anthropic 正确解析缓存创建与读取字段，OpenAI 正确解析缓存命中字段，字段缺失时为零且不报错。（F4、N6）
- AC7：双重强化——“优先使用专用工具”和“编辑前必须先读取”同时出现在稳定系统提示与相关工具描述中。（F5）
- AC8：补充消息注入——补充消息使用 `<system-reminder>` 标签，模型按照提醒行动但不复述或直接回答提醒；消息不进入持久历史和 TUI。（F6、N3）
- AC9：Plan Mode 按轮次注入——`/plan` 后第 1、6、11……轮注入完整提醒，其他轮次注入精简提醒；仅开放只读工具；`/do` 恢复全部工具并按计划执行。（F7）
- AC10：跨协议一致——Anthropic 与 OpenAI 都使用相同的系统模块、环境信息和补充消息，并保持相同的注入节奏；缓存差异只由对应 LLM Client 处理。（F8）
- AC11：不破坏 ch04——多轮 Agent Loop、用户取消、历史一致、流式错误恢复和现有测试继续成立。（N2）
- AC12：历史合法——首轮、工具结果回灌续轮和 Plan Mode 多轮请求均保持角色顺序与工具配对合法；中途取消后再次提问能够继续，不产生消息结构相关的 400。（N3）
- AC13：环境采集降级——在非 Git 目录、Git 不可用或单项采集失败时，对应信息省略或降级；界面不冻结，请求正常发起。（N4）
- AC14：代码质量与安全——完整测试、格式和 lint 检查通过；环境信息、调试输出和错误中不出现 API Key；新增模块或提醒类型不需要修改装配主循环。（N5、N7、N8）
